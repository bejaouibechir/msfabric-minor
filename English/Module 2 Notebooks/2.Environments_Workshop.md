# Workshop: Environments in Notebooks

## Why the Environments?

A Fabric Environment centralizes Python libraries and Spark configuration, and shares them among all the notebooks in the workspace.

Without an environment, each notebook must install its libraries on startup:

```python
# ❌ Mauvaise pratique — installation répétée dans chaque notebook
%pip install plotly scikit-learn
```

With an Environment:

- libraries are **installed once**
- they are **shared** between all the notebooks of the workspace
- Spark configuration is **centralised**
- the environment is **versionable** and deployable via CI/CD

---

## Part 1 — Creating the Environment

1. In the workspace, click **+ New item**
2. Search and select **Environment**
3. Nommer l'environnement : **`env_data_science`**
4. Cliquer **Create**

---

## Part 2 — Discover the Environment menu

The interface consists of three sections in the left menu:

### Libraries

| Sous-section              | Role                                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Built-in**              | Pre-installed libraries by Fabric (not editable). Ex:`plotly 5.22.0`is already available by default |
| **External repositories** | Add libraries from PyPI (pip)                                                                    |
| **Custom**                | Upload custom packages (file`.whl`or`.jar`)                                                       |

### Spark compute

| Sous-section         | Role                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **Acceleration**     | Enable **Native execution engine** to accelerate Spark jobs                       |
| **Compute**          | Configure the Spark pool: node size, driver/executor memory, dynamic allocation |
| **Spark properties** | Add Spark custom properties (e.g.`spark.sql.shuffle.partitions`)                   |

### Storage

| Sous-section  | Role                                                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Resources** | Upload files (config, certificates, reference data) available in all notebooks in this environment |

## Part 4 — Adding libraries from PyPI

1. Click **External restitories** in the left menu
2. Two modes are available:
   - **Full mode**: complete resolution of dependencies (recommended, safer)
   - **Quick mode**: faster, fewer checks
3. Rester en **Full mode**
4. Click the button **+ Add library** → select **Add library from public restory**
5. Choisissez  **PyPI** de **Public repository**
6. Saisir `[scikit-learn]()` → valider
7. To add a **second library**, click on **+ Add library** → **Add library from public restory**
8. Saisir `great-expectations` → valider

| Library         | Usage               |
| -------------------- | ------------------- |
| `scikit-learn`       | Machine learning    |
| `great-expectations` | Data quality |

> The **+ Add library** button offers two options — **public restitory** (PyPI) or **private restitory** (Azure Artifacts private feed or other). For standard libraries, always choose **public restitory**.

**What you need to see on screen**:

- libraries listed with their solved version

### Alternative — Via file requirements.txt

1. Create a file locally`requirements.txt` :

```text
scikit-learn
great-expectations
```

2. Click **Import YML** top center then **Upload to Full mode**
3. Fabric automatically solves compatible versions

## Part 5 — Configure Spark

### 5.1 — Compute

1. Click **Compute** in the left menu
2. Observe the default settings of **Starter Pool**:

| Parameter             | Default         |
| --------------------- | ------------------------- |
| Node family           | Auto (Memory optimized)   |
| Node size             | Medium                    |
| Spark driver core     | 8                         |
| Spark driver memory   | 56 GB                     |
| Spark executor core   | 8                         |
| Spark executor memory | 56 GB                     |
| Dynamic allocation    | Activated (1 to 9 executers) |

> For a workshop on small volumes, these default values are sufficient. Do not change unless specifically required.

### 5.2 — Spark properties

1. Click **Spark properties** in the left menu
2. Cliquer **Add properties**
3. Renseigner :

| Property name                  | Value |
| ------------------------------ | ----- |
| `spark.sql.shuffle.partitions` | `8`   |

4. Cliquer **Confirm**

> Reduce`spark.sql.shuffle.partitions`8 (instead of 200 by default) accelerates processing on small volumes of data.

### 5.3 — Acceleration

1. Click **Accession** in the left menu
2. Check **Enable native execution engine** if you want to speed up Spark jobs

> The native execution engine is free and has no impact on billing. It is recommended to activate it.

## Part 6 — Publish the Environment

Changes are only active after publication.

1. Click **Publish** at the top left at the menu level **Home**
2. Confirmer
3. Wait until installation is complete (a few minutes)

**What you need to see on screen**:

- the status goes to **Published**



---

## Part 7 — Attaching the Environment to a Notebook

### Option A — Manually in the notebook

1. Open a notebook
2. At the top of the notebook, click on the environment selector (next to Runtime)
3. Select **`env_data_science`**
4. Wait for Spark session initialization

### Option B — Default for all workspace

1. Go to **Workspace settings** → **Data Engineering / Science**
2. Select **`env_data_science`** as default environment
3. Cliquer **Confirm**
