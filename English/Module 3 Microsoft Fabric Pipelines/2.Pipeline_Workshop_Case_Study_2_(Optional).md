# Workshop 2: Full Medallion Architecture — Bronze → Silver → Gold with orchestration

## Context: Urban transition to an intelligent energy grid

## Background

A **smart city** upgrades its power grid by deploying 100 IoT sensors to monitor consumption, detect anomalies and reduce energy losses.

### 1. Status

Raw data arrive continuously and must be cleaned, enriched with reference thresholds, and analyzed for incidents.

- **100 IoT** sensors deployed in 4 quarters
- **7200 records** over 3 days (real time data)
- **50 incidents** detected automatically
- **Unstructured raw data** requiring cleaning
- **Reference table** with warning thresholds by sensor type

### 2. Issue

**How to transform raw IoT data (Bronze) into cleaned and enriched data (Silver), detecting anomalies, applying business rules and closing with Until to deal with unresolved incidents? **

Contraintes :

- 
- 
- Filter active sensors with **If Condition**
- 
- Trace detected anomalies

### 3. Solution : Pipeline de transformation intelligent

Pipeline qui :

1. ** Charges** the 5 CSV to Bronze tables (without`_` ni `-`)
2. **Lit** the reference table with **Lookup**
3. **Copy** and **transform** Bronze → Silver
4. **Filter** valid data with **If Condition**
5. **Column** with **Until** until incident resolution
6. **Trace** treatments

- **Use query** : **T-SQL Query**
- **Query** :

```sql
SELECT
    infra.[Quartier],
    infra.[TypeCapteur],
    monitoring.[CapteurID],
    monitoring.[Timestamp],
    TRY_CAST(monitoring.[Consommation_kWh] AS DECIMAL(18, 2)) AS Consommation_kWh,
    TRY_CAST(monitoring.[Tension_V] AS DECIMAL(10, 2))        AS Tension_V,
    TRY_CAST(monitoring.[Frequence_Hz] AS DECIMAL(10, 3))     AS Frequence_Hz,
    TRY_CAST(monitoring.[FacteurPuissance] AS DECIMAL(10, 3)) AS FacteurPuissance,
    TRY_CAST(monitoring.[Temperature_C] AS DECIMAL(10, 2))    AS Temperature_C,
    monitoring.[Qualite_Signal]
FROM LH_Energie_Bronze.dbo.monitoring AS monitoring
INNER JOIN (
    SELECT CapteurID, Quartier, TypeCapteur
    FROM LH_Energie_Bronze.dbo.infrastructures
    WHERE Statut = 'Actif'
) AS infra
    ON monitoring.CapteurID = infra.CapteurID
```

> `Qualite_Signal`remains a text column (`Bon`, `Moyen`, etc.): it should not be converted into`DECIMAL`. Digital measurements use`TRY_CAST`with explicit precision in order to keep their decimals and avoid the complete failure of the copy if a value is invalid.

### Guided Analysis Questions

#### Question 1: Volume of IoT data

**See table`monitoring`** :

```sql
SELECT COUNT(*) as TotalReleves FROM monitoring
```

** Expected result**: 7200 readings

** Interpretation**:

- 7200 3-day surveys = 2400 surveys/day
- 2400 readings/day ÷ 100 sensors = 24 readings/sensor/day
- **Conclusion**: Each sensor sends **1 reading per hour** (24h × 3 days = 72 readings/sensor)



---

#### Question 2: Geographical distribution

**See table`infrastructures`** :

```sql
SELECT Quartier, COUNT(*) as NbCapteurs 
FROM infrastructures 
GROUP BY Quartier
ORDER BY NbCapteurs DESC
```

**Result achieved**:

| Neighbourhood             | Nb Sensors |
| -------------------- | ----------- |
| Quartier_Residentiel | 28          |
| Centre_Ville         | 26          |
| Zone_Commerciale     | 23          |
| Zone Industrielle    | 23          |

** Interpretation**:

- **Slightly uneven distribution** of sensors (23-28 by area)
- **Residential Quarter** is best covered (28 sensors), consistent with higher population density
- **Industrial area and Commercial area** are less covered (23 sensors each), which may represent a risk if consumption is more variable or higher

**Trade Impact**: The coverage is generally satisfactory, but particular attention should be paid to the Industrial Zone — less covered but potentially at higher risk of energy anomaly. It would be appropriate to add 2 to 5 additional sensors to balance monitoring.

---

#### Question 3: Sensor condition

**See table`infrastructures`** :

```sql
SELECT Statut, COUNT(*) as NbCapteurs
FROM infrastructures
GROUP BY Statut
```

** Expected result**:

| Status         | Nb Sensors |
| -------------- | ----------- |
| Actif          | 55          |
| En_Maintenance | 27          |
| En_Panne       | 5           |

** Interpretation**:

- **55%** of sensors are operational (55/100)
- **27%** are in maintenance
- **5%** failed (En Panne)
- **13%** have uninformed status (55+27+5 = 87 out of 100)

**Job impact**: Availability rate below recommended threshold (< 70%). There is an urgent need to plan the commissioning of En Maintenance sensors and to invest En Panne sensors to at least 70% availability.

---

#### Question 4: Criticality of incidents

**See table`incidents`** :

```sql
SELECT Severite, COUNT(*) as NbIncidents
FROM incidents
GROUP BY Severite
ORDER BY 
  CASE Severite 
    WHEN 'Critique' THEN 1 
    WHEN 'Haute' THEN 2 
    WHEN 'Moyenne' THEN 3 
    WHEN 'Faible' THEN 4
  END
```

** Expected result**:

| Severite | Nb Incidents |
| -------- | ------------ |
| Critique | 8            |
| Haute    | 16           |
| Moyenne  | 12           |
| Faible   | 14           |

** Interpretation**:

- **16%** of critical incidents (8/50) → require immediate response ****
- **32%** high severity incidents (16/50) → **priority**
- **24%** average severity incidents (12/50) → schedule within 48h
- **28%** low severity incidents (14/50) → ongoing monitoring

The criticality pyramid is **inverted**: too many serious incidents compared to weak incidents.

**Trade Impact**: This incident profile reveals a live network. It is imperative to deal urgently with the 24 critical/high incidents before they impact the city's electrical distribution. Enhanced preventive maintenance is recommended.

## Analysis of results

Open **LH Energy Gold** → **SQL analytics endpoint**, then execute the following queries.

### Question 1: Consumer profile by neighbourhood

**Observez `goldconsoparquartier`** → SQL Analytics Endpoint :

```sql
SELECT Quartier, ROUND(AVG(MoyenneConso_kWh), 2) AS ConsoMoyenne
FROM goldconsoparquartier
GROUP BY Quartier
ORDER BY ConsoMoyenne DESC
```

** Interpretation**: The district with the highest average consumption reveals the priority areas for energy optimisation.

---

### Question 2: Most critical incidents

**Observez `goldincidents`** :

```sql
SELECT TypeIncident, Severite, NbIncidents, TempsResolutionMoyen_Min
FROM goldincidents
WHERE Severite = 'Critique'
ORDER BY NbIncidents DESC
```

** Interpretation**: The most frequent critical incidents guide investments in preventive maintenance.

---

### Question 3: KPI network availability

**Observez `goldmetriques`** :

```sql
SELECT Quartier,
       ROUND(AVG(Taux_Disponibilite_Pct), 2) AS DisponibiliteMoyenne,
       ROUND(AVG(Pertes_Energie_Pct), 2)     AS PertesMoyennes
FROM goldmetriques
GROUP BY Quartier
ORDER BY DisponibiliteMoyenne ASC
```

** Interpretation**: The area with the lowest availability is the intervention priority. A rate < 95% is considered critical in a smart grid.
