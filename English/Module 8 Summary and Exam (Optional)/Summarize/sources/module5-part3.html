Block 2 — Table Date DimDate

💡 Why a table Date? Without a dedicated date table, Power BI cannot make time comparisons (previous week, same month last year), nor properly sort months by name. A DimDate is indispensable to exploit the temporal dimension.

2.1 — Create the DimDate table in LH SolarVoix (Notebook)

⚠️ Why in the Lakehouse? The semantic model SM_SolarVoix_Appels fonctionne en mode Direct Lake : it reads the data of LH_SolarVoix mais has no writing rights. It is impossible to create a calculated DAX table. The table DimDate must therefore be created directly in the Lakehouse and then referenced by the model.

Step 2 — Generate DimDate with Silver calls enriched dates

The date range is calculated directly from silver_appels_enrichis[date_appel] to ensure consistency.

from pyspark.sql import functions as F
from pyspark.sql.types import DateType

<a id="read-date-plage-since-silvercallesenriched></a>
# Read the date range from silver calls enrichis
df calls = spark.table("silver calls enriched")
date range = df calls.agg(
F.min(F.col("date appeal").cast(DateType())).alias("date min"),
F.max(F.col("date appeal").cast(DateType())).alias("date max")
.collect()[0]

date min = foreign date["date min"]
date max = date range["date max"]
print(e"Date Range: {date min} → {date max}")

<a id="generate-the-sequence-of-dates>/a>
# Generate date sequence
df dim = spark.sql(e" & quot;
SELECT sequence(
TO DATE('{date min}'),
TO DATE('{date max}'),
INTERVAL 1 DAY
) AS date array
Select(F.explode("date array").alias("Date"))

Add-all-temporal-sized columns
# Add all columns of temporal dimension
df dimdate = df dim.select(
F.col("Date quot;),
F.year("Date").alias("Year"),
F.concat(F.lit("T"), F.ceil(F.month("Date") / 3).cast("string")).alias("Tri-month"),
F.month("Date").alias("Month Num"),
F.date format("Date",MMMM").alias("Name Month"),
F.date format("Date", quot;yyyy-MM").alias("Year Month"),
F.weekofyear("Date").alias("Week")
F.dayofweek("Date").alias("Day Week"), # 1=Dim ... 7=Sam (Spark)
F.date format("Date",EEEEE").alias("Name Day"),
F.when(F.dayofweek("Date").isin([1, 7]), True).otherwise(False).alias("Est Weekend")
)

-Writer-in-the-lakehouse-in-mode-overwrite-quot;
# Write in Lakehouse in Overwrite mode
df dimdate.write.format("delta").mode("overwrite").saveAsTable("DimDate")

print(e"Table DimDate created: {df dimdate.count()} lines")
df dimdate.show(5)

These 6 measures are only used to power the Min / Max / Target fields of gauges and visuals Goal.

Groupe B — Mesures de base

Mesure B1 — Score Churn Moyen

Score Churn Moyen =
AVERAGE(silver_appels_enrichis[score_risque_churn])

Mesure B2 — Taux Alertes Critiques

Taux Alertes Critiques =
DIVIDE(
    COUNTROWS(FILTER(silver_appels_enrichis, silver_appels_enrichis[alerte_critique] = TRUE())),
    COUNTROWS(silver_appels_enrichis),
    0
)

Format: Percentage, 1 decimal

Mesure B3 — Nb Appels en Alerte

Nb Appels en Alerte =
CALCULATE(COUNTROWS(silver_appels_enrichis), silver_appels_enrichis[alerte_critique] = TRUE())

Mesure B4 — Total Appels

Total Appels =
COUNTROWS(silver_appels_enrichis)

Mesure B5 — Seuil Danger P90

Seuil Danger P90 =
PERCENTILE.INC(silver_appels_enrichis[score_risque_churn], 0.90)

Measure B6 — Negative Churn score 

Negative Churn score =
CALCULATE(
AVERAGE(silver calles enrichis[score risk churn]),
silver enriched calls[sentiment ia] = negative quot;
)

Mesure B7 — Score Churn Hors Positif

Score Churn Hors Positif =
CALCULATE(
    AVERAGE(silver_appels_enrichis[score_risque_churn]),
    silver_appels_enrichis[sentiment_ia] <> "positif"
)

Measure B8 — Rate Termination 

Termination rate =
DIVIDE(
CALCULATE(COUNTROWS(silver calls enrichis), silver calls enriched[int detect] = quot;resiliation"),
COUNTROWS(silver calles enrichis),
0
)

Format: Percentage, 1 decimal

Measure B9 — Duration Moy Critical Calls 

Duration Moy Critical Calls =
CALCULATE(
AVERAGE(silver calles enrichis[dure minutes]),
silver calls enriched[critical alert] = TRUE()
)

Group C — Comparison and deviation measures

Measure D1 — Difference Negative vs Medium 

Negative Difference vs Average =
[Score Churn Negative] - [Score Churn Medium]

Format: Decimal number, 1 decimal

If this measure is +15, negative calls score 15 points above the overall average. This quantifyes the impact of negative sentiment on the risk of churn.

Measure D2 — Ratio Score Not Positive vs Negative 

Ratio Not Positive vs Negative =
DIVIDE([Churn Rating Not Positive], [Churn Rating Negative], 0)

Format: Percentage, 1 decimal

If the ratio is close to 100%, neutral calls have almost the same score as negative ones — neutral feeling is actually as risky. If the ratio is 60%, neutrals are significantly less risky.

Measure D3 — Ratio Termination vs. Alerts 

Ratio Termination vs Alerts =
DIVIDE([Rate Termination], [Rate Critical Alerts], 0)

Format: Percentage, 1 decimal

If this ratio is greater than 100%, there are more intentions of termination than critical alerts generated — the alert system: some at-risk customers go under radar.

Measure D4 — Critical Duration vs Global Duration 

Critical Duration vs Global =
[Duration Moy Appeals Reviews] - AVERAGE(silver calles enrichis[duree minutes])

Format: Decimal number, 1 decimal

If +3 min, each alert consumes 3 minutes more than a normal call.

Group D — Quality measures IA

Measurement Q1 — Precision IA 

Accuracy IA =
DIVIDE(
CALCULATE(
COUNTROWS(silver calles enrichis),
silver calls enrichis[sentiment ia] = silver calls enrichis[sentiment reel]
),
COUNTROWS(silver calles enrichis),
0
)

Format: Percentage, 1 decimal

Direct measurement of the reliability of model IA. If 80%, the model correctly predicts feeling in 80% of cases.

Measure Q2 — Intention Rate Actual Termination 

Rate Intention Actual Termination =
DIVIDE(
CALCULATE(
COUNTROWS(silver calles enrichis),
silver appeals enriched[intention release] =
),
COUNTROWS(silver calles enrichis),
0
)

Format: Percentage, 1 decimal

Compared to Rate Termination (based on intent_detecte), this measure uses field truth. If the gap is large, the model lacks actual termination intentions.

Measurement Q3 — Detection Rate Resilience 

 Detection Rate Termination =
DIVIDE([Rate Termination], [Rate Intention Actual Termination], 0)

Format: Percentage, 1 decimal

A < 100% score means that the model lacks actual cases of termination.

CREATE VIEW v_sentiments_par_produit AS
SELECT
    produit,

    COUNT(*)                                          AS nb_appels,
    ROUND(AVG(CAST(score_risque_churn AS FLOAT)), 1)  AS score_churn_moyen,

FROM silver_appels_enrichis
GROUP BY produit, sentiment_ia;

SELECT * FROM v_sentiments_par_produit ORDER BY produit, sentiment_ia;

Vue 3 — Comparaison sentiment_ia vs sentiment_reel (matrice de confusion SQL)

CREATE VIEW v_precision_ia AS
SELECT
    sentiment_reel,
    sentiment_ia,
    COUNT(*)                                        AS nb_appels,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY sentiment_reel), 1) AS pct_dans_classe
FROM silver_appels_enrichis
GROUP BY sentiment_reel, sentiment_ia;

-- Confusion matrix: rows = real, columns = predicted
SELECT * FROM v precision ia ORDER BY sentiment reel, sentiment ia;

-- Overall accuracy
SELECT
ROUND(100.0 * SUM(CASE WHEN sentiment ia = sentiment reel THEN 1 ELSE 0 END) / COUNT(*), 1)
AS precision pct
FROM silver calls enrichis;

View 4 — Actual intentions vs. detected by product

CREATE VIEW v intention comparison AS
SELECT
product,
Release intention,
detect,
CUNT(*) AS nb calls,
ROUND(AVG(CAST(score risk churn AS FLOAT)), 1) AS score mean,
CASE WHEN intention reelle =intent detecte THEN 'CORRECT' ELSE 'ERROR' END AS detection ok
FROM silver calls enrichis
GROUP BY product, purpose reelle, intent detecte;

-- Correct detection rate per product
SELECT product,
CUNT(*) AS nb total,
SUM(CASE WHEN detection ok = 'CORRECT' THEN 1 ELSE 0 END) AS nb correct,
ROUND(100.0 * SUM(CASE WHEN detection ok = 'CORRECT' THEN 1 ELSE 0 END) / COUNT(*), 1) AS precision pct
FROM v intention comparison
GROUP BY product
ORDER BY precision pct;

Vue 5 — Tendance hebdomadaire

CREATE VIEW v_tendance_hebdomadaire AS
SELECT
    DATEPART(YEAR, date_appel)  AS annee,
    DATEPART(WEEK, date_appel)  AS semaine,
    sentiment_ia,
    COUNT(*)                                         AS nb_appels,
    ROUND(AVG(CAST(score_risque_churn AS FLOAT)), 1) AS score_moyen
FROM silver_appels_enrichis
GROUP BY DATEPART(YEAR, date_appel), DATEPART(WEEK, date_appel), sentiment_ia;
