Layer 1 — RBAC Workspace

security workshop. Step 1 — Assign the Workspace Viewer role to the

participating account. lens. Assign the Viewer role to the participating account and understand the impact of this role on overall security.

Pourquoi :
Workspace Viewer is the only role that does not allow any dangerous modification or execution. It constitutes the security ceiling for all end users. The Admin and Member roles automatically bypass the RLS, the OLS and most item-level restrictions. This is why you must always start from the Viewer role before applying finer security.

  5. From the drop-down list of roles, choose Viewer.

  6. Click the Add.

Actions participant :

  1. button. Log in to Microsoft Fabric with the participant.

  2. account. Open the FinCorp_Initial.

workspace. What you need to see :

  • No button Edit, Delete, New or Manage is available.

  • The participant can only open the reports and view the data according to inherited permissions.

Step 2 — Remove ReadAll from Lakehouse

lens. : Delete ReadAll permission. on the Lakehouse item to block access to raw files and tables in the Lakehouse interface.

Pourquoi :
Permission ReadAll (Read all with Apache Spark) allows direct access to files and tables via Lakehouse Explorer (Tab Files and Tables). Without this permission, the participant can no longer view or preview raw data, even if he retains Read permission. inherited from Workspace Viewer. This enhances security while keeping ReadData on the SQL analytics endpoint for the DirectLake report.

  4. Choisissez Manage permissions.

  6. Choisissez Remove ReadAll.

  7. Confirm deletion.

Layer 3 — Safety of the semantic model (RLS / CLS)

Step 1 — Implementing Row-Level Security (RLS)

Objective : Restrict access to dataset lines so that the participant can only see the authorized data according to his business scope.

Pourquoi :
The Row-Level Security allows dynamic filtering of visible lines in the semantic model depending on the connected user. It is the main mechanism for securing analytical data in a ruled Fabric environment. Without RLS, a Viewer user can view all accessible lines via the dataset.

Actions formateur (compte dev – Workspace Admin) :

  1. Open the semantic model SM_SalesFinCorp.

  2. Click Security.

  3. Click + New role.

  4. Name the role: SalesRegion_Filter.

  5. Select the table containing the column Region.

  6. Add the rule:

Region = USERPRINCIPALNAME()

  1. Save the rule.

  2. Add account participant Role SalesRegion_Filter.

  3. Save the configuration.

Actions participant :

  1. Log in with the account participant.

  2. Open the Power BI dataset related report SM_SalesFinCorp.

What you need to see :

  • The participant only sees the lines corresponding to its perimeter.

  • Other regions disappear from visuals.

  • Aggregations of the ratio are automatically recalculated according to the filter applied.
