Pipeline Workshop – Case Study 1

Workshop 1: Multi-source dynamic ingestion with validation

Context: Optimizing a renewable energy supply chain

One usine de production traditionnelle decides to migrate to a solar-windian hybrid model. Energy data comes from multiple sensors and systems (current consumption, solar production, wind production, battery storage).

1. Status

  • 3 data sources quotidiennes :
  • besoins_energetiques.csv (consommation horaire de l'usine)
  • production_solaire.csv (return of panels per area)
  • production_eolienne.csv (turbine data)
  • Unstructured deposit : files placed manually in a folder
  • Absence de validation : impossible to know if all sources have arrived
  • Processus manuel : a technician checks and imports files in Excel

2. Issue

How to automate the ingestion of heterogeneous energy data to analyse current needs and identify available renewable sources, without manual intervention and with validation of completeness?

Contraintes :

  • Dynamically detect which files are present
  • Create a Bronze table by energy source

3. Solution : Pipeline d'ingestion intelligent

Pipeline that scans, filters, copies and automatically tracks all energy sources to Bronze.

Activity 2: RecoveryTrace (Set Variable)

  1. Activities → General → glissez Set Variable on the canvas

  4. Onglet General :

  • Name : RecupererTracage
  1. Onglet Settings :
  • Variable name : select FichiersTraites
  • Value : click Add dynamic content
  • Copy and paste:

@variables('FichiersTemp')

  • Click OK

💡 Astuce : RecupererTracage copy the current state of FichiersTemp in FichiersTraites every iteration. At the end of the loop, FichiersTraites contains the complete list of processed files.

⚠️ Why two activities? Fabric interdit l'expression @union(variables('FichiersTraites'), array(item().name)) in a Set Variable because the variable cannot refer itself (self-referencing variable error). The pattern FichiersTemp → FichiersTraites bypass this limitation.

Question 1: Validation of the completeness of sources

Interpretation :

Business impact : If a file is missing tomorrow (e.g. production solar.csv), the variable NombreFichiers would be = 2 instead of 3, which would trigger an alert.

Question 2: Temporal granularity of energy needs

Analyze table besoins_energetiques :

SELECT CUNT(*) as NbRelevants FROM energy needs
-- Result: 168 lines

Calculate the measurement frequency :

168 7-day surveys = 168 / 7 = 24 surveys/day
24 readings/day = 1 reading/hour

Interpretation :

  • Hourly Granularity : Consumption is measured every hour

  • Period : 7 jours complets (1 semaine type)

  • Accuracy : Sufficient to identify peak consumption

Business impact : Allows to analyze consumption patterns (day/night, weekday/weekend) and adjust production accordingly.

Example of further analysis :

SELECT 
    DATEPART(hour, Horodatage) as Heure,
    AVG(Consommation_kWh) as Conso_Moyenne
FROM besoins_energetiques
GROUP BY DATEPART(hour, Horodatage)
ORDER BY Heure

Insight expected : Identify peak hours (ex: 8am-6pm for a factory)

Question 4: Wind capacity and measurement frequency

Analyze table production_eolienne :

SELECT CUNT(*) as NbReleves FROM production eolian
-- Result: 840 lines

Calculate the number of turbines and frequency :

840 readings / 168 hours (7j × 24h) = 5 turbines
5 readings per hour = 1 reading every 12 minutes per turbine

Interpretation :

  • High frequency : 1 measures every 12 minutes

  • Fine Granularity : To detect rapid wind variations

Business impact : The high frequency makes it possible to adjust the consumption in near real time according to the wind production (e.g. to launch energy-efficient machines when the wind blows strong).

Business Insights

Insight 1: Preliminary energy balance

Calculate theoretical renewable capacity :

-- Average solar output
SELECT AVG(Production kWh) as Prod Solar Medium
From solar production
-- Expected result: ~350 kWh/day (25 panels × 14 kWh)

-- Average wind production
SELECT AVG(Production kWh) as Prod Eolienne Moyenne
FROM production eolian
-- Expected result: ~1200 kWh/day (5 turbines × 240 kWh)

-- Daily energy requirement
SELECT SUM(Consumption kWh) / 7 as Conso Quotidienne
From energy needs
-- Expected result: ~1800 kWh/day

Analyse de couverture :

Renewable production: 350 (solar) + 1200 (wind) = 1550 kWh/day
Energy requirement: 1800 kWh/day
Coverage rate: (1550 / 1800) × 100 = 86%
Deficit: 1800 - 1550 = 250 kWh/day (14%)

Interpretation :

  • 86% energy autonomy with renewable sources
  • 14% deficit to be filled (traditional network or batteries)
  • Achieved : Significant reduction in network dependence

💡 Trade recommendations :

  1. Add 5 panneaux solaires additional (+70 kWh/d) to reach 90% autonomy
  2. Install a battery system 250 kWh to store surplus and cover peaks
  3. Implement a intelligent discharge system to carry forward certain non-priority expenses

Insight 2 : Patterns temporels de consommation

Identify peak hours :

SELECT 
    DATEPART(hour, Horodatage) as Heure,
    AVG(Consommation_kWh) as Conso_Moyenne,
    MAX(Consommation_kWh) as Conso_Max
FROM besoins_energetiques
GROUP BY DATEPART(hour, Horodatage)
ORDER BY Conso_Moyenne DESC

Expected result (peak hours) :

Heure Conso Moyenne Conso Max
14h 95 kWh 110 kWh
15h 92 kWh 105 kWh
10h 88 kWh 100 kWh

Interpretation :

  • Pic de consommation : 14h-15h (heures de production maximale de l'usine)

  • Coincidence : Maximum solar production also during this period

  • Opportunity : Synchronisation naturelle production solaire / consommation

Trade recommendations :

  • Optimiser : Launch the energy-generating processes between 12pm and 4pm (maximum solar)

  • Different : Recharge batteries and preheat equipment early morning (night wind)

  • Avoid : Do not launch large consumers between 6 p.m. and 10 p.m.

Insight 3: Variable wind production

Analyze stability :

SELECT 
    TurbineID,
    AVG(Production_kWh) as Prod_Moyenne,
    STDEV(Production_kWh) as Ecart_Type,
    MIN(Production_kWh) as Prod_Min,
    MAX(Production_kWh) as Prod_Max
FROM production_eolienne
GROUP BY TurbineID

Expected result :

Turbine Moyenne Standard deviation Min Max Coefficient variation
EOL-01 10 kWh 4.2 kWh 0 18 42%
EOL-02 10 kWh 4.5 kWh 0 19 45%
... ... ... ... ... ...

Interpretation :

  • High variability : Coefficient de variation ~40-45%

  • Unpredictability : Fluctuous production from 0 to 18-19 kWh

  • Besoin de stockage : Batteries are essential to smooth production

Trade recommendations :

  • Court terme : 500 kWh battery system (covers 6 hours of deficit)

  • Moyen terme : Backup contract with the traditional network

  • Long terme : Diversify with a 2nd predictable source (hydroelectric if possible)
