# Workshop 1 — From notebook to production script with Spark Job Definition

## Quick approach

1. Load three JSON files in`Files/landing_sjd/`.
2. Test their reading and transformation in a Fabric notebook.
3. Load`energie_sjd_utils.py`in the integrated resources of the notebook.
4. Create a Spark Job Definition with`ingestion_energie.py`as the main file.
5. Add`energie_sjd_utils.py`as a reference file.
6. Associate`LH_Energie_Bronze`as the default Lakehouse.
7. Run the job for the three datasets.
8. Check the Delta tables and demonstrate the fit of the`MERGE`.
9. Examine newspapers for success and controlled failure.
10. Call Spark Job Definition from a sequential pipeline.

---

## Objectives

This workshop transforms exploratory ingestion into a PySpark program set and executable as **Spark Job Definition** in Microsoft Fabric.

At the end of the workshop, you will know:

- test the treatment in a notebook without starting`argparse` ;
- use a Python module placed in the integrated resources of the notebook;
- Create and configure a Spark Job Definition;
- play OneLake files or a REST API;
- writing in Delta tables with a`MERGE` idempotent ;
- supervise the job and call it from a pipeline.

**Indicative duration:** 3 h

**Level:** advanced

**Language:** Python and PySpark

## Workshop architecture

The workspace used is`WS_Energie_Renouvelable`and Lakehouse is`LH_Energie_Bronze`.

| Element | Local location |
| --- | --- |
| JSON data | `workshop 1 input data/sortie/` |
| Generator | `workshop 1 input data/generate_workshop1_data.py` |
| Script principal | `workshop 1 scripts/ingestion_energie.py` |
| Module utilitaire | `workshop 1 scripts/energie_sjd_utils.py` |

The identifiers accepted by the code are exactly:

| Dataset | File | Target table | Key to MERGE |
| --- | --- | --- | --- |
| `besoins` | `besoins.json` | `besoins_energetiques_sjd` | `Timestamp` + `Zone` |
| `production-solaire` | `production-solaire.json` | `production_solaire_sjd` | `PanneauID` + `Date` |
| `production-eolienne` | `production-eolienne.json` | `production_eolienne_sjd` | `TurbineID` + `Timestamp` |

> Always use`production-solaire`and`production-eolienne`. Values`solaire`and`eolien`are not accepted by`argparse`.

The treatment writes only in suffixed tables`_sjd`.

# Part 3 — Understanding scripts

## Step 6 — Utility Module

`energie_sjd_utils.py`contains:

- dictionary`DATASETS` ;
- file names, tables and business keys;
- `schema_brut()`to build the`StructType` ;
- `typer_dataframe()`to convert types and add technical columns.

## Step 7 — Main Script

`ingestion_energie.py` :

1. reads the arguments with`argparse` ;
2. select the source`files`or`api` ;
3. creates the DataFrame with the explicit schema;
4. applies conversions;
5. refuses the null keys;
6. eliminate duplicates from the lot;
7. creates the Delta table or executes a`MERGE` ;
8. writes information and errors in newspapers.

Arguments accepted:

```text
--source files|api
--dataset besoins|production-solaire|production-eolienne
--landing-path Files/landing_sjd
--base-url https://...        # uniquement avec --source api
```

# Part 4 — Creating Spark Job Definition

## Step 8 — Create item

1. In`WS_Energie_Renouvelable`, select **New item**.
2. Recherchez **Spark Job Definition**.
3. Nommez l'item `TEST_SJD_Ingestion_Energie`.
4. Choisissez **PySpark**.
5. Validez.

## Step 9 — Add Files

1. Add`ingestion_energie.py`as **Main definition file**.
2. Add`energie_sjd_utils.py`as **Reference file**.
3. Enregistrez.

In Spark Job Definition, the import remains:

```python
from energie_sjd_utils import DATASETS, dataset_config, schema_brut, typer_dataframe
```

Do not use`from builtin...`in Spark Job Definition. The prefix`builtin`refers only to the resources of a notebook.

## Step 10 — Associate Lakehouse

1. Open the Spark Job Definition settings.
2. Select`LH_Energie_Bronze`as the default Lakehouse.
3. Use the Starter Pool for exercise.
4. Enregistrez.

Without default Lakehouse,`Files/landing_sjd`and Delta tables cannot be solved.

## Step 11—Defining the Three Run Configurations

In command line arguments, successively use the following three exact commands:

```text
--source files --dataset besoins --landing-path Files/landing_sjd
--source files --dataset production-solaire --landing-path Files/landing_sjd
--source files --dataset production-eolienne --landing-path Files/landing_sjd
```

> ⚠️ `eolien`and`solaire`Only disabled people. Accepted values are`production-eolienne`and`production-solaire`.

Before each launch, check:

- Main file:`ingestion_energie.py` ;
- reference:`energie_sjd_utils.py` ;
- Lakehouse : `LH_Energie_Bronze` ;
- dataset: one of the three exact values above.

# Part 6 — Call the job from a pipeline

## Step 17 — Creating the Pipeline

# Quick troubleshooting

| Error | Cause | Correction |
| --- | --- | --- |
| `No module named builtin.energie_sjd_utils` | Resource missing from the notebook | Load file in **Integrated resources** |
| `No module named energie_sjd_utils`in the SJD | Reference missing | Add file as **Reference file** |
| `invalid choice: solaire` | Mauvais dataset | Use`production-solaire` |
| `invalid choice: eolien` | Mauvais dataset | Use`production-eolienne` |
| `Files/landing_sjd` introuvable | Lakehouse or missing files | Attach Lakehouse and control files |
| No table | Job failed or bad Lakehouse | View logs and configuration |
| 60 lines after two executions | Add instead of`MERGE` | Use`fusionner_delta()`provided script |
| API failed | Incorrectly stopped service or URL | Back to Mode`files` |
