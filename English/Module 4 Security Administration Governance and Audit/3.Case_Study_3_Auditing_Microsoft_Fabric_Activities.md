You will build a workshop **Audit SQL** focused solely on the **Warehouse** Microsoft Fabric:

- enable SQL Audit Logs (with detailed solution for Save button)
- Reproducible tests between Admin and Viewer

- Fine analysis of executed commands (who did what, when, what command?)

## Part 2 - Enable SQL Audit Logs and Prepare Data

### 2.1. - Enable SQL Audit Logs (only with Admin) – Ultra-Detailed Steps

1. Open the Warehouse`WH_RetailCorpAuditDemo`with`participant@contactemeraudeit.onmicrosoft.com`
2. In the **page of the Warehouse** (open SQL editor), click on the **Settings** icon (gear up right)
3. In the panel that opens, in the left menu, click **SQL audit logs**
4. You are now on the page **SQL audit logs (preview)**
5. Check that the toggle **Save events to SQL audit logs** is on **On** (green)
6. **If the Save button at the bottom of the page remains grayed/disabled** (common behaviour in Preview):
   - In the **Log sound** section, temporarily change the **Years** value from 9 to **1**
   - Or, in **Events to record**, uncheck the **Select all** box, wait for 1 second, then tick **Select all**
   - Or turn off the main toggle **Save events to SQL audit logs**
7. The **Save** button must now become active (greyer)
8. Click **Save**

**What you need to see on screen**:  
The Save button becomes clickable, then a confirmation message appears. Status remains **On**.

> ** Important note**: The Fabric interface often disables the Save button as long as no changes are detected. A small modification (even temporary) is required to activate.

## Part 4 - Create and Use Custom View`vw_audit_logs`

### 4.1 - Get IDs from the workspace and warehouse

1. In the Warehouse tab, copy the browser's full URL
2. Extract the two GUIDs:`{workspaceId}`and`{warehouseId}`

### 4.2 - Create the custom view`vw_audit_logs`

1. With`participant@contactemeraudeit.onmicrosoft.com`
2. New SQL query
3. Paste (replace GUID):

```sql
CREATE OR ALTER VIEW vw_audit_logs AS
SELECT 
    event_time,
    action_id,
    succeeded,
    server_principal_name AS utilisateur,
    statement AS commande_executee,
    session_id,
    client_ip
FROM sys.fn_get_audit_file_v2(
    'https://onelake.blob.fabric.microsoft.com/{workspaceId}/{warehouseId}/Audit/sqldbauditlogs/',
    DEFAULT, DEFAULT, DEFAULT, DEFAULT)
WHERE event_time > DATEADD(MINUTE, -60, GETUTCDATE());
GO
```

4. Run

### 4.3 - View

```sql
SELECT * FROM vw_audit_logs
ORDER BY event_time DESC;
```

## Part 5 - Real observations (Admin vs Viewer)

This view allows to see **all SQL activity** on the warehouse **WH DetailCorpAuditDemo**.

### 2. Analysis of main columns

| Colonne               | Signification                                                                  | Remarques                                                  |
| --------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **event_time**        | Date and time of event (with milliseconds)                      | Sorted by DESC → most recent first                |
| **action_id**         | Audited Action Code (most important to understand what happened) | See details below                                     |
| **succeeded**         | 1 = success, 0 = failure                                                          | All at 1 here                                               |
| **utilisateur**       | Account that executed the action                                                  | Ici : `participant@contactemeraudeit.onmicrosoft.com`      |
| **commande_executee** | Full T-SQL query executed                                             | Very useful for investigation                            |
| **session_id**        | SQL Session Identifier                                                  | Allows to group actions of the same connection       |
| **client_ip**         | Client IP address                                                           | Ici `204.43.41.207`(probably your position or a stronghold) |

### 3. Decoding **action id** as seen

| action_id | Signification       | Contexte courant                                                   |
| --------- | ------------------- | ------------------------------------------------------------------ |
| **DBL**   | **Database Logout** | Logout                                                        |
| **SL**    | **SELECT**          | Data reading                                                 |
| **BCM**   | **Batch Completed** | End of a batch (often group SELECT, INSERT, etc.) |

**Other frequent codes you will probably see:**

- `AL` → ALTER
- `CR` → CREATE
- `DR` → DROP
- `EX`→ EXECUTE (stocked procedures)
- `IN` → INSERT
- `UP` → UPDATE
- `DL` → DELETE

> **Note** : `BCM`is very common when the audit is configured in "Batch Completed Group" mode. It captures the end of execution of almost all requests.

- **Utilisateur unique** : `participant@contactemeraudeit.onmicrosoft.com`
- **Very dense activity** around **17:45:59** on 06/05/2026.
- Many **SL** (SELECT) and **BCM** → user explores the schema (`SELECT default_schema_name...`, `SELECT TOP ...`, `COALESCE`, etc.).
- Some **EXEC** to configure the session context (`sp_set_session_context`).
- Conventional discovery requests (exploring objects, limits of results, etc.).
- **IP constant** → same position/client.

It is a typical **activity of a user who discovers or develops** on the Warehouse (Power BI Desktop, DAX Studio, Azure Data Studio, or Fabric Studio).

### 5. Interest Security / Governance

This view is **very powerful** for:

- Detect unauthorized access
- Identify who changed the scheme (DDL)
- Find long or problematic queries
- Do forensics (who saw such a table?)
- Meet standards such as ISO 27001, SOC2, GDPR, etc.

**Conseils de bon usage :**

1. **Filtrer intelligemment** :
   
   ```sql
   SELECT * FROM vw_audit_logs
   WHERE event_time >= DATEADD(hour, -24, GETUTCDATE())
     AND action_id IN ('SL','IN','UP','DL','AL','CR','DR')
   ORDER BY event_time DESC;
   ```

2. Create alerts about`action_id`(ALTER, DROP, GRANT, etc.) or on certain users.

3. Monitor changes to or connections outside the usual time zones.

### Encore plus

Creating a dedicated view for alerting is a best practice in governance and security. This makes logic cleaner, easier to maintain and reuse.

```sql
CREATE OR ALTER VIEW vw_alert_hors_horaires
AS
SELECT 
    event_time,
    action_id,
    utilisateur,
    commande_executee,
    client_ip,
    session_id,
    succeeded
FROM vw_audit_logs
WHERE (
        -- Hors horaires de travail
        DATEPART(weekday, event_time) IN (1, 7)                    -- Samedi et Dimanche
        OR DATEPART(hour, event_time) >= 19                        -- Après 19h00
        OR DATEPART(hour, event_time) < 8                          -- Avant 08h00
      )
  AND action_id IN ('UP', 'DL', 'IN', 'AL', 'CR', 'DR', 'EX', 'SL')  -- Actions sensibles + SELECT
  -- AND utilisateur <> 'participant@contactemeraudeit.onmicrosoft.com'  -- Décommente si tu veux exclure ton compte
;
```

> Tip: Schedule (19 and 8) according to your actual working hours.

Once the view is created:
In SQL editor, run this simple query:

```sql
SELECT * 
FROM vw_alert_hors_horaires
WHERE event_time >= DATEADD(minute, -10, GETUTCDATE())   -- dernières 10 minutes
ORDER BY event_time DESC;
```

Click on the "Create rule" button (top).
Set the rule as follows:

Rule name : Alert - Off Schedule Activity
Query: The above request (SELECT * FROM vw alert out times WHERE ...)
Run query every : 5 minutes
Condition : On each event
Action: Message to individuals → Participant (and add email if needed)
