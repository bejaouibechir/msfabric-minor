# Workshop: Real-time wind farm monitoring — Eventstream & KQL Database

## Objective

You will ingest simulated IoT data (wind turbine sensors) in **Microsoft Fabric** via **Eventstream**, store them in a **KQL Database**, convert them into real time, analyze them with **KQL** queries, view them in a **Real-Time Dashboard**, speed up the dashboard with **Materialized View** and configure **automatic alerts** with **Activator**.

## Files required

- `wind_turbine_simulator.py`— Python script provided in Part 2.3
- Package Python : `azure-eventhub`

## Prerequisite

- Holding Microsoft Fabric with **Real-Time Intelligence** enabled
- Licence **Trial** or **Capacity** compatible Fabric
- An existing **workspace Fabric**
- **Python 3.9+** installed on your station
- Internet access to send events from the Python simulator to the endpoint generated by Fabric

#### Create script

Create a file **`wind_turbine_simulator.py`** and paste this code:

```python
import json
import time
import random
from datetime import datetime, timezone
from azure.eventhub import EventHubProducerClient, EventData

# ============================================================
# CONFIGURATION — Coller vos valeurs depuis l'Eventstream
# ============================================================
CONNECTION_STR = "<votre_connection_string_primary_key>"
EVENTHUB_NAME = "<votre_event_hub_name>"
# ============================================================

TURBINES = ["WT-001", "WT-002", "WT-003", "WT-004", "WT-005"]
PARK_NAME = "Parc Eolien Bizerte"

def generate_turbine_event(turbine_id):
    wind_speed = random.uniform(3.0, 25.0)

    # Courbe de puissance simplifiee
    if wind_speed < 3.5:
        power = 0
    elif wind_speed > 22:
        power = 0
    else:
        power = min(3000, (wind_speed - 3.5) ** 2 * 18)

    rotor_rpm = wind_speed * 1.2 + random.uniform(-1, 1)
    gen_temp = 55 + (power / 3000) * 35 + random.uniform(-3, 3)
    vibration = 2.0 + random.uniform(0, 1.5)

    # Injection d'anomalies (10% du temps)
    # Option atelier intensif :
    # Pour observer plus vite les anomalies pendant une demo courte,
    # vous pouvez temporairement remplacer 0.10 par 0.25 ou 0.30.
    # Revenez ensuite a 0.10 pour garder un flux plus realiste.
    if random.random() < 0.10:
        anomaly_type = random.choice(["overheat", "vibration", "underperform"])
        if anomaly_type == "overheat":
            gen_temp += random.uniform(25, 45)
        elif anomaly_type == "vibration":
            vibration += random.uniform(5, 12)
        elif anomaly_type == "underperform":
            power *= random.uniform(0.2, 0.5)

    return {
        "TurbineId": turbine_id,
        "Timestamp": datetime.now(timezone.utc).isoformat(),
        "WindSpeedMs": round(wind_speed, 2),
        "RotorRPM": round(rotor_rpm, 2),
        "PowerOutputKW": round(power, 2),
        "GeneratorTempC": round(gen_temp, 2),
        "VibrationMmS": round(vibration, 2),
        "NacelleOrientation": round(random.uniform(0, 360), 1),
        "AmbientTempC": round(random.uniform(15, 35), 1),
        "ParkName": PARK_NAME
    }

def main():
    producer = EventHubProducerClient.from_connection_string(
        conn_str=CONNECTION_STR,
        eventhub_name=EVENTHUB_NAME
    )
    print("Envoi d'evenements vers Fabric Eventstream...")

    try:
        while True:
            batch = producer.create_batch()
            for turbine_id in TURBINES:
                event = generate_turbine_event(turbine_id)
                batch.add(EventData(json.dumps(event)))
                print(f"  [{event['Timestamp'][:19]}] {turbine_id} | "
                      f"Vent: {event['WindSpeedMs']}m/s | "
                      f"Puissance: {event['PowerOutputKW']}kW | "
                      f"Temp: {event['GeneratorTempC']}C | "
                      f"Vibration: {event['VibrationMmS']}mm/s")
            producer.send_batch(batch)
            print(f"  -> Batch de {len(TURBINES)} evenements envoye\n")
            time.sleep(5)
    except KeyboardInterrupt:
        print("Arret du simulateur.")
    finally:
        producer.close()

if __name__ == "__main__":
    main()
```

### 4.1 — Quick check

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| take 20
```

- **`extend`**: Create a new column`EventTime` en convertissant `Timestamp` (texte → date/heure).

- **`take 20`**: Returns 20 arbitrary lines for an immediate overview.

**What you see**: the last ingested events, with raw telemetry columns and possibly enriched columns.

---

### 4.2 — Average turbine output (last 10 minutes)

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(10m)
| summarize
    AvgPower = avg(PowerOutputKW),
    AvgWind = avg(WindSpeedMs),
    EventCount = count()
  by TurbineId
| order by AvgPower desc
```

- **`where EventTime > ago(10m)`**: Filter the last 10 minutes.

- **`summarize ... by TurbineId`**: Group by turbine and average/occurrence calculation.

- **`order by AvgPower desc`**: The most productive to least productive class.

**What you see**: Each turbine with its average power, average wind speed and number of recent events.

---

### 4.3 — Detection of thermal anomalies (> 95°C)

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| where GeneratorTempC > 95
| project EventTime, TurbineId, GeneratorTempC, PowerOutputKW, WindSpeedMs
| order by GeneratorTempC desc
```

- **`where GeneratorTempC > 95`**: Critical threshold beyond the risk of breakage.

- **`project`**: Keeps only the columns useful for diagnosis.

- **`order by GeneratorTempC desc`** : The warmest first.

**What you see**: only events where the generator exceeded 95°C.

---

### 4.4 — Abnormal vibration detection (> 8 mm/s)

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| where VibrationMmS > 8.0
| project EventTime, TurbineId, VibrationMmS, RotorRPM, GeneratorTempC
| order by VibrationMmS desc
```

- **`where VibrationMmS > 8.0`** : Seuil de vibration dangereuse.

- Same 4.3 but applied to vibrations.

**What you see**: events with dangerous vibrations.

---

### 4.5 — Energy efficiency per turbine (5 min window)

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| where WindSpeedMs between (4.0 .. 20.0)
| summarize
    AvgPower = avg(PowerOutputKW),
    AvgWind = avg(WindSpeedMs)
  by TurbineId, bin(EventTime, 5m)
| extend EfficiencyRatio = AvgPower / (AvgWind * AvgWind * AvgWind) * 1000
| order by EventTime desc, TurbineId
```

- **`bin(EventTime, 5m)`**: Group events in 5 minutes.

- **`extend EfficiencyRatio = ... / (AvgWind³) * 1000`**: Simplified efficiency (power/wind3).

- Useful for comparing efficiency between turbines with equal wind.

**What you see**: a simplified efficiency ratio per turbine every 5 minutes.

---

### 4.6 — Overall health of turbines

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| summarize
    AvgTemp = avg(GeneratorTempC),
    MaxTemp = max(GeneratorTempC),
    AvgVibration = avg(VibrationMmS),
    MaxVibration = max(VibrationMmS),
    AvgPower = avg(PowerOutputKW),
    TotalEvents = count()
  by TurbineId
| extend HealthStatus = case(
    MaxTemp > 95 or MaxVibration > 8.0, "CRITIQUE",
    MaxTemp > 85 or MaxVibration > 6.0, "ATTENTION",
    "NORMAL")
| order by HealthStatus asc, TurbineId asc
```

- **`case(...)`**: Status`CRITIQUE`/`ATTENTION`/`NORMAL`.

- Synthesis by turbine on max temperature, max vibration, average power.

- **`order by HealthStatus asc`** : First go up the most critical.

**What you see**: a summary table with a status **CRITICAL**, **AUTENTION** or **NORMAL** per turbine.

### 4.7 — Temperature slippery curve (granularity 1 minute)

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(1h)
| summarize AvgTemp = avg(GeneratorTempC) by TurbineId, bin(EventTime, 1m)
| order by EventTime asc
```

- **`bin(EventTime, 1m)`** : Aggregates per minute.

- Ideal for an online **graphic** where one follows the evolution minute per minute.

**What you see**: an ideal time series for an online graph.

### 4.8 — Detection of underperformance by comparison of power/wind

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| where WindSpeedMs between (6.0 .. 20.0)
| extend ExpectedPowerKW = min_of(3000.0, pow(WindSpeedMs - 3.5, 2) * 18.0)
| extend PerformanceRatio = iif(ExpectedPowerKW == 0, real(null), PowerOutputKW / ExpectedPowerKW)
| where PerformanceRatio < 0.60
| project EventTime, TurbineId, WindSpeedMs, PowerOutputKW, ExpectedPowerKW, PerformanceRatio
| order by PerformanceRatio asc
```

- **`pow(WindSpeedMs - 3.5, 2) * 18.0`**: Expected theoretical power.

- **`PerformanceRatio < 0.60`**: The turbine produces less than 60% of the expected → underperformance.

**What you see**: cases where the power actually produced is far below the expected power.

### 4.10 — Joint with a small reference table

```kql
let TurbineReference = datatable(TurbineId:string, SiteArea:string, NominalPowerKW:real, CommissionYear:int)
[
    "WT-001", "Nord-Ouest", 3000.0, 2021,
    "WT-002", "Nord-Ouest", 3000.0, 2021,
    "WT-003", "Centre", 3000.0, 2022,
    "WT-004", "Centre", 3000.0, 2022,
    "WT-005", "Sud", 3000.0, 2023
];
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(15m)
| summarize AvgPower = avg(PowerOutputKW), MaxTemp = max(GeneratorTempC) by TurbineId
| join kind=leftouter TurbineReference on TurbineId
| extend LoadPct = round((AvgPower / NominalPowerKW) * 100.0, 2)
| project TurbineId, SiteArea, CommissionYear, AvgPower, LoadPct, MaxTemp
| order by LoadPct desc
```

- **`let TurbineReference = datatable(...)`**: Temporary table (site, year, nominal power).

- **`join kind=leftouter`**: Enriches telemetry data with metadata.

- **`LoadPct = round(AvgPower / NominalPowerKW * 100, 2)`** : Charge relative.

**What you see**: an analysis enriched by reference metadata.

### 4.11 — Top 3 anomalies per combined score

```kql
TurbineEvents
| extend EventTime = todatetime(Timestamp)
| where EventTime > ago(30m)
| extend ExpectedPowerKW = min_of(3000.0, pow(WindSpeedMs - 3.5, 2) * 18.0)
| extend UnderPerfPenalty = iif(WindSpeedMs >= 8 and PowerOutputKW < ExpectedPowerKW * 0.6, 25.0, 0.0)
| extend TempPenalty = iif(GeneratorTempC > 95, 50.0, iif(GeneratorTempC > 85, 20.0, 0.0))
| extend VibPenalty = iif(VibrationMmS > 8, 40.0, iif(VibrationMmS > 6, 15.0, 0.0))
| extend AnomalyScore = TempPenalty + VibPenalty + UnderPerfPenalty
| where AnomalyScore > 0
| top 3 by AnomalyScore desc
| project EventTime, TurbineId, GeneratorTempC, VibrationMmS, PowerOutputKW, WindSpeedMs, AnomalyScore
```

- **Three penalties added**: underperformance (25), overheating (20/50), vibration (15/40).

- **`top 3 by AnomalyScore desc`**: The most serious events first.

**What you see**: the 3 most worrying events, ranked according to a combined score.

### 4.12 — Recent production trend compared to two windows

```kql
let CurrentWindow =
    TurbineEvents
    | extend EventTime = todatetime(Timestamp)
    | where EventTime between (ago(10m) .. now())
    | summarize CurrentAvgPower = avg(PowerOutputKW) by TurbineId;
let PreviousWindow =
    TurbineEvents
    | extend EventTime = todatetime(Timestamp)
    | where EventTime between (ago(20m) .. ago(10m))
    | summarize PreviousAvgPower = avg(PowerOutputKW) by TurbineId;
CurrentWindow
| join kind=inner PreviousWindow on TurbineId
| extend DeltaPower = CurrentAvgPower - PreviousAvgPower
| extend Trend = case(DeltaPower > 150, "HAUSSE", DeltaPower < -150, "BAISSE", "STABLE")
| project TurbineId, PreviousAvgPower, CurrentAvgPower, DeltaPower, Trend
| order by DeltaPower asc
```

- **Two sub-requests**: current window (10m) vs previous window (20m to 10m).

- **`join`then`case(...)`** : Compare the average powers →`HAUSSE` / `BAISSE` / `STABLE`.

**What you see**: if each turbine is up, down or stable from the previous window.

### 5.7 — Seventh tile: top anomalies

1. In the **Home** tab, click **Newtile**
2. Paste this request:

```kql
TurbineEvents

| extend ExpectedPowerKW = min_of(3000.0, pow(WindSpeedMs - 3.5, 2) * 18.0)
| extend UnderPerfPenalty = iif(WindSpeedMs >= 8 and PowerOutputKW < ExpectedPowerKW * 0.6, 25.0, 0.0)

| extend VibPenalty = iif(VibrationMmS > 8, 40.0, iif(VibrationMmS > 6, 15.0, 0.0))
```

- **`AnomalyScore = somme des pénalités`**: The higher the score, the more problems the event has.

- **`top 10 by AnomalyScore desc`** : Remount the 10 most serious events first.

## Part 6 — Industrial Alert Pipeline : Update Policy + Function + Materialized View

In this part, you will build a ** complete alerting system** entirely in the Eventhouse, without external dependence. The final architecture is:

`TurbineEvents` → *(Update Policy)* → `fn_DetectAnomaly()` → `TurbineAlerts` → *(Materialized View)* → `MV_AlertSummary` → *(Dashboard)*

> **Why this approach?** The Update Policy is a native mechanism of the Eventhouse: every time ingested in`TurbineEvents`, the detection function automatically executes and writes anomalies in`TurbineAlerts`. No email, no Teams, no external dependency. Alerts are immediately requestable and visible in the dashboard.

### 6.1 — Creating the TurbineAlerts table

1. Ouvrir **WindFarmEventhouse_queryset**
2. Paste and execute this command:

```kql
.create table TurbineAlerts (
    AlertTime: datetime,
    TurbineId: string,
    AlertType: string,
    Severity: string,
    AlertValue: real,
    Threshold: real,
    Message: string
)
```

3. Cliquer **Run**

**What you need to see**: a message of success. The table`TurbineAlerts`appears in the left panel under **Tables**.

### 6.2 — Create fn detectAnomaly detection function

The detection logic of the 3 types of anomalies is centralized in a single reusable function. The Update Policy will call this function — if you want to add a rule, you only change the function.

1. Paste and execute this command:

```kql
.create-or-alter function fn_DetectAnomaly() {
    TurbineEvents
    | extend EventTime = todatetime(Timestamp)
    | extend ExpectedPowerKW = min_of(3000.0, pow(WindSpeedMs - 3.5, 2) * 18.0)
    | extend PerformanceRatio = iif(
        ExpectedPowerKW == 0 or WindSpeedMs < 6.0 or WindSpeedMs > 20.0,
        real(null),
        PowerOutputKW / ExpectedPowerKW)
    | where GeneratorTempC > 95
        or VibrationMmS > 8
        or (isnotnull(PerformanceRatio) and PerformanceRatio < 0.60)
    | extend AlertType = case(
        GeneratorTempC > 95, "SURCHAUFFE",
        VibrationMmS > 8,    "VIBRATION",
                             "SOUS_PERFORMANCE")
    | extend AlertValue = case(
        GeneratorTempC > 95, GeneratorTempC,
        VibrationMmS > 8,    VibrationMmS,
                             round(PerformanceRatio * 100, 1))
    | extend Threshold = case(
        GeneratorTempC > 95, 95.0,
        VibrationMmS > 8,    8.0,
                             60.0)
    | extend Severity = case(
        GeneratorTempC > 120 or VibrationMmS > 14, "CRITIQUE",
                                                    "ATTENTION")
    | extend Message = strcat(
        AlertType, " sur ", TurbineId,
        " — Valeur: ", tostring(round(AlertValue, 2)),
        " / Seuil: ", tostring(Threshold))
    | project AlertTime = EventTime, TurbineId, AlertType, Severity, AlertValue, Threshold, Message
}
```

2. Cliquer **Run**

**What you need to see**: a message of success. The function`fn_DetectAnomaly`appears under **Functions** in the left panel.

> `fn_DetectAnomaly()`in the queryet and check that lines of anomalies appear.

### 6.3 — Activer l'Update Policy

1. Paste and execute this command:

```kql

@'[{"IsEnabled": true, "Source": "TurbineEvents", "Query": "fn_DetectAnomaly()", "IsTransactional": false, "PropagateIngestionProperties": false}]'
```

2. Cliquer **Run**

**What you need to see**: a success message confirming activation.

> `TurbineEvents`, Fabric automatically executes`fn_DetectAnomaly()`and writes the anomalies in`TurbineAlerts`. The pipeline is active in real time.

`TurbineEvents`. It applies only to new ingestions. Wait for a simulator cycle (5 seconds) before checking.

## Part 7 — Materialized View on TurbineEvents

> **Recall**: One`MV_AlertSummary`on`TurbineAlerts`has already been established in Part 6.4. This part creates a second Materialized View,`mv_turbine_health_1m`, on the raw table`TurbineEvents`. Both views have distinct roles:`MV_AlertSummary`aggravate alerts,`mv_turbine_health_1m`aggregates raw telemetry to accelerate the operational dashboard tiles.

In a real context, dashboards often perform the same aggregations permanently. One **Materialized View** pre-calculates the results once and updates them incrementally.

### 7.1 — Create mv turbine health 1m

1. In **WindFarmEventhouse**, click **+ New** → **Materialized view**
2. Replace the content with the following command:

```kql
.create-or-alter materialized-view with (backfill=true) mv_turbine_health_1m on table TurbineEvents
{
    TurbineEvents
    | extend EventTime = todatetime(Timestamp)
    | summarize
        AvgPower = avg(PowerOutputKW),
        MaxTemp = max(GeneratorTempC),
        MaxVibration = max(VibrationMmS),
        AvgWind = avg(WindSpeedMs),
        EventCount = count()
      by TurbineId, bin(EventTime, 1m)
}
```

3. Cliquer **Run**

**What you need to see**: a message of success.`mv_turbine_health_1m`appears under **Materialized views**.

> `backfill=true`immediately recalculates all historical data. The five aggregates (power, temperature, vibration, wind, count) are pre-calculated per turbine per minute.

### 7.2 — Check the view

```kql
mv_turbine_health_1m
| where EventTime > ago(30m)
| order by EventTime desc
| take 20
```

**What you need to see**: one line per turbine per minute, with columns`AvgPower`, `MaxTemp`, `MaxVibration`, `AvgWind`, `EventCount`.

### 7.3 — Use view in dashboard

Replace expensive dashboard queries with view queries:

```kql
mv_turbine_health_1m
| where EventTime > ago(1h)
| project EventTime, TurbineId, MaxTemp
```

```kql
mv_turbine_health_1m
| where EventTime > ago(1h)
| project EventTime, TurbineId, MaxVibration
```

> Keep the table raw`TurbineEvents`for detailed exploration and both Materialized Views for real-time operational display.

A Materialized View is not a total replacement of the raw table. It accelerates well-identified repetitive aggregations.
