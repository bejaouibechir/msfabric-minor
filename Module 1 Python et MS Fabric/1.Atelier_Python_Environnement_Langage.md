## 📝 Cellule 1 : Vérification de l'environnement et techniques d'importation

### 🔍 Avant d'exécuter

- **`import`** : charge un **module**, c'est-à-dire un fichier Python contenant du code déjà écrit (`sys`, `pathlib`, `json`…). Presque toutes les cellules en commencent par là.
- **Six écritures** à connaître, toutes présentes dans la cellule : `import x`, `import x as y`, `from x import a`, `from x import a as b`, `import x.y` et l'import à partir d'un **texte**.
- **Contrôle** : `sys.executable` dit quel Python exécute le code ; il doit passer par `.venv`. `sys.version` doit afficher 3.11 ou plus.
- **Où Python cherche les modules** : expliqué à la Partie 6.

### 💻 Code

```python
# === CELLULE 1 : Vérification de l'environnement et techniques d'importation ===

# Technique 1 : « import module ». On garde le nom complet : on écrira ensuite « sys.version ».
import sys

# Technique 2 : « import module as alias ». On donne un nom court au module.
# C'est l'usage courant pour les bibliothèques de données (« import pandas as pd »).
import platform as pf

# Technique 3 : « from module import objet ». On importe UN objet précis, utilisable sans préfixe.
from pathlib import Path

# Technique 4 : « from module import objet as alias ». Comme la 3, avec un autre nom
# (utile quand deux modules proposent le même nom).
from datetime import datetime as dt

# Technique 5 : « import paquet.sous_module ». Un paquet est un dossier de modules ; on écrira « os.path.xxx ».
import os.path

# Technique 6 : import à partir d'un TEXTE. Utile quand le nom du module vient d'un fichier de configuration.
from importlib import import_module
module_json = import_module("json")

# ❌ À éviter : « from module import * » importe tous les noms d'un coup et peut écraser vos propres variables.

# --- Vérification de l'environnement (utilise les imports ci-dessus)
print(f"Python         : {sys.version.split()[0]}")             # technique 1 : préfixe « sys. »
print(f"Implémentation : {pf.python_implementation()}")          # technique 2 : alias « pf »
print(f"Système        : {pf.system()} {pf.machine()}")
print(f"Interpréteur   : {sys.executable}")                       # le Python qui exécute cette cellule
print(f"Dossier actif  : {Path.cwd()}")                           # technique 3 : « Path » sans préfixe
print(f"Dans un venv   : {sys.prefix != sys.base_prefix}")        # True si un environnement virtuel est actif

# --- Les autres techniques en action
print(dt(2025, 1, 3).strftime("%d/%m/%Y"))                        # technique 4 : alias « dt »
print(os.path.basename("data/sites_reference.csv"))               # technique 5 : os.path.xxx
print(module_json.dumps({"site": "SITE_IND_001"}))                # technique 6 : module obtenu par son nom
```

### 📤 Résultat

Exemple sous Windows (les valeurs des six premières lignes varient selon votre poste) :

```

Implémentation : CPython
Système        : Windows AMD64
Interpréteur   : C:\Users\formation\formation_python_fabric\.venv\Scripts\python.exe
Dossier actif  : C:\Users\formation\formation_python_fabric
Dans un venv   : True
03/01/2025
sites_reference.csv

```

### 💡 Interprétation

- **Version** : 3.11 ou plus est nécessaire ; sinon `tomllib`, `StrEnum` et `except*` (vus plus loin) échoueront.
- **Chemin de l'interpréteur** : il doit passer par `.venv`. Si `Dans un venv` vaut `False`, le notebook n'utilise pas votre environnement : relancez `jupyter notebook` depuis un terminal où `.venv` est activé.
- **Préfixe ou pas** : avec `import sys`, on écrit `sys.version` ; avec `from pathlib import Path`, on écrit `Path` seul. Le préfixe indique d'où vient le nom, ce qui aide à relire le code.
- **Alias** : `pf` et `dt` sont des noms locaux ; ils n'existent que dans **votre** notebook.
- **`import *`** : il rend impossible de savoir d'où vient un nom ; les équipes le proscrivent.
- **Dans Fabric** : `sys.version` identifie le runtime (Runtime 1.3 : Python 3.11 ; Runtime 2.0 : Python 3.13).

## 📝 Cellule 2 : Premier contact : `print`, commentaires, indentation

### 🔍 Avant d'exécuter

- **Commentaire** : tout ce qui suit `#` sur une ligne est ignoré par Python ; c'est une note pour le lecteur.
- **`print`** : affiche du texte. En Python 3, c'est une **fonction** : on écrit `print(...)` avec des parenthèses. `sep` change le séparateur entre les éléments, `end` ce qui termine la ligne.
- **Indentation** : le décalage en début de ligne (4 espaces) délimite un **bloc**. Après une ligne qui finit par `:` (comme `if ...:`), le bloc indenté ne s'exécute que si la condition est vraie.

```python
# ❌ Python 2 — SyntaxError en Python 3 (à reconnaître, pas à écrire)
print "Réseau EnergiaNord : 6 sites"
print "Chargement...",              # la virgule finale supprimait le retour à la ligne
```

### 💻 Code

```python
# === CELLULE 2 : print, commentaires, indentation ===
# Ceci est un commentaire : Python l'ignore.

print("Réseau EnergiaNord : 6 sites")                 # affichage simple, retour à la ligne automatique

# sep : ce qui sépare les éléments (par défaut un espace)
print("Site", "SITE_IND_001", "5.0 MW", sep=" | ")   # affiche : Site | SITE_IND_001 | 5.0 MW

# end : ce qui termine la ligne (par défaut un retour à la ligne)
print("Chargement...", end=" ")                       # reste sur la même ligne
print("terminé")                                      # complète la ligne précédente

# Des parenthèses permettent de couper une longue instruction sur plusieurs lignes
message = ("Mesures toutes les 15 minutes "
           "sur 6 sites")
if len(message) > 20:                                 # len() compte les caractères ; la ligne finit par « : »
    print(f"Message de {len(message)} caractères")    # ligne indentée = dans le bloc du « if »
```

### 📤 Résultat

```
Réseau EnergiaNord : 6 sites
Site | SITE_IND_001 | 5.0 MW
Chargement... terminé
Message de 41 caractères
```

### 💡 Interprétation

- **`sep` et `end`** : ils remplacent les astuces de ponctuation de Python 2 (la virgule finale).
- **Le `:` et l'indentation** : c'est la seule « ponctuation » structurelle du langage ; pas d'accolades ni de `end`.
- **Piège fréquent** : du code collé depuis un e-mail ou un site web perd souvent son indentation ; l'erreur n'apparaît qu'à l'exécution (`IndentationError`).
- **`len(message)`** : 34 caractères, donc le test `> 20` est vrai et la ligne s'affiche.

## 📝 Cellule 3 : Variables et typage dynamique

### 🔍 Avant d'exécuter

- **Variable** : un **nom** qui désigne une valeur. `capacity_mw = 5.0` signifie « le nom `capacity_mw` désigne la valeur `5.0` ».
- **Type** : la nature de la valeur (texte `str`, entier `int`, décimal `float`, vrai/faux `bool`). C'est la **valeur** qui porte le type, pas le nom.
- **`None`** : « aucune valeur ». C'est l'équivalent de `NULL` en SQL.
- **snake_case** : convention de nommage en minuscules avec `_` (`capacity_mw`).

### 💻 Code

```python
# === CELLULE 3 : Variables et typage dynamique ===

# Création de cinq variables : on écrit « nom = valeur »
site_id = "SITE_IND_001"       # texte (str)
capacity_mw = 5.0              # nombre décimal (float)
flexible = True                # booléen (bool) : True ou False, avec une majuscule
nb_mesures = 720               # nombre entier (int)
curtailment_price = None       # None : ce site n'a pas de prix d'effacement

# Affichage : pour chaque variable, son nom, sa valeur et son type
# (« !r » montre la valeur telle qu'on l'écrirait en code, avec les guillemets pour un texte)
for nom, valeur in [("site_id", site_id), ("capacity_mw", capacity_mw),
                    ("flexible", flexible), ("nb_mesures", nb_mesures),
                    ("curtailment_price", curtailment_price)]:
    print(f"{nom:<18} {valeur!r:<16} {type(valeur).__name__}")

# Typage dynamique : le même nom peut désigner, plus tard, une valeur d'un autre type
x = 10                         # x désigne un entier
x = "dix"                      # x désigne maintenant un texte : c'est autorisé
print(type(x).__name__)        # str

# Un booléen est aussi un entier : True vaut 1 et False vaut 0
print(isinstance(flexible, int))   # True : « flexible » (un bool) est reconnu comme un int
```

## 📝 Cellule 4 : Nombres : division, flottants, `Decimal`

### 🔍 Avant d'exécuter

- **Trois divisions** : `/` donne toujours un nombre décimal (`7 / 2` → `3.5`), `//` donne le quotient entier (`3`), `%` donne le reste (`1`).
- **Le piège des décimaux (`float`)** : l'ordinateur calcule en **binaire**. Comme `1/3` s'écrit `0,333…` sans fin en base 10, le nombre `0.1` n'a pas d'écriture finie en base 2 : il est stocké avec une minuscule erreur. Résultat visible : `0.1 + 0.2` donne `0.30000000000000004` et non `0.3`.
- **Conséquence** : ne comparez jamais deux décimaux avec `==`. Utilisez `math.isclose(a, b)`, qui accepte un écart infime.
- **`Decimal`** : nombre décimal **exact**, calculé en base 10 ; à utiliser pour les montants d'argent.

```python
# ❌ Python 2 — comportement supprimé
print 7 / 2            # affichait 3 : division ENTIÈRE entre deux entiers
```

### 💻 Code

```python
# === CELLULE 4 : Nombres — division, flottants, Decimal ===
import math
from decimal import Decimal

# --- 1) Les opérateurs arithmétiques
print(7 / 2)       # 3.5   : « / » donne toujours un nombre décimal
print(7 // 2)      # 3     : « // » donne la division entière (quotient)
print(7 % 2)       # 1     : « % » donne le reste de la division
print(2 ** 10)     # 1024  : « ** » élève à la puissance

# --- 2) Le piège des nombres décimaux (float)
somme = 0.1 + 0.2                                  # on additionne deux décimaux
print("0.1 + 0.2 vaut          :", somme)          # 0.30000000000000004 : un minuscule écart apparaît
print("0.1 + 0.2 == 0.3 ?      :", somme == 0.3)   # False : la comparaison exacte échoue à cause de cet écart

# À la place de « == », on compare avec une tolérance
print("math.isclose(somme, 0.3):", math.isclose(somme, 0.3))   # True : l'écart infime est accepté

# --- 3) Decimal : calcul exact, pour les montants
# On lui passe des TEXTES (« "0.1" »), pas des décimaux, pour éviter l'erreur de départ.
print("Decimal :", Decimal("0.1") + Decimal("0.2"))            # 0.3 exactement
```

### 📤 Résultat

```

0.1 + 0.2 == 0.3 ?      : False

Decimal : 0.3
```

### 💡 Interprétation

- **Les trois divisions** : `7 / 2` = `3.5`, `7 // 2` = `3`, `7 % 2` = `1`. L'ambiguïté de Python 2 (où `7 / 2` donnait `3`) a disparu.
- **`0.1 + 0.2`** : le résultat est `0.30000000000000004`, donc la comparaison `== 0.3` est **fausse**. Ce n'est pas un bug de Python : c'est la limite du calcul binaire.
- **Même comportement partout** : pandas, NumPy et Spark ont le même écart ; les calculs du réseau EnergiaNord sont concernés.
- **Règle** : comparer avec `math.isclose` (ou une tolérance), jamais avec `==`.
- **`Decimal("0.1") + Decimal("0.2")`** : donne exactement `0.3` ; à réserver aux montants, car plus lent que `float`.

## 📝 Cellule 5 : Nombres : arrondi, grands entiers, `NaN` et `None`

### 🔍 Avant d'exécuter

- **`round`** : arrondit **au pair le plus proche** quand la décimale est exactement 5. `round(2.5)` donne `2` et `round(3.5)` donne `4`.
- **Grands entiers** : un `int` n'a pas de limite de taille (`2 ** 100` fonctionne). Le `_` sépare les milliers pour la lisibilité (`1_000_000`).
- **`NaN`** (*Not a Number*) : un décimal particulier qui représente un résultat indéfini. Il n'est **jamais égal à lui-même**.
- **`None` et `NaN`** : `None` = « pas de valeur » (n'est pas un nombre) ; `NaN` = un « nombre » indéfini.

### 💻 Code

```python
# === CELLULE 5 : Arrondi, grands entiers, NaN et None ===

# --- Arrondi : au pair le plus proche quand la décimale est exactement 5
print(round(0.5), round(1.5), round(2.5), round(3.5))   # 0 2 2 4 : 0.5 -> 0 (pair), 1.5 -> 2, 2.5 -> 2 (pair), 3.5 -> 4

# --- Grands nombres
print(1_000_000 * 1.5)          # 1500000.0 : le « _ » est ignoré, il sert seulement à la lecture
print(2 ** 100)                 # un entier de 31 chiffres : aucune limite de taille

# --- NaN : un résultat indéfini
valeur_nan = float("nan")                               # on crée un NaN à partir du texte "nan"
print(valeur_nan == valeur_nan)                         # False : un NaN n'est égal à rien, pas même à lui-même
print(math.isnan(valeur_nan))                           # True : c'est la bonne façon de le détecter

# --- None : l'absence de valeur
print(None == 0)                                        # False : None n'est pas zéro
print(None is None)                                     # True : on teste None avec « is »
```

### 📤 Résultat

```

2.67
1500000.0
1267650600228229401496703205376
False
True
False
True
```

### 💡 Interprétation

- **`0 2 2 4`** : ce résultat surprend beaucoup de participants ; c'est l'arrondi « au pair » de Python.
- **Point d'attention Fabric** : `round` de **Python et de pandas** arrondit au pair, alors que `round` de **Spark SQL** arrondit « demi vers le haut » (`HALF_UP`). Spark propose `bround` pour l'arrondi au pair. Un même calcul peut donc différer entre un notebook pandas et un notebook PySpark.
- **`round(2.675, 2)` = `2.67`** : `2.675` n'est pas représentable exactement en binaire (même cause qu'à la cellule précédente).
- **`NaN`** : `valeur_nan == valeur_nan` est `False` ; on le détecte avec `math.isnan` (ou `isna()` en pandas), jamais avec `==`.
- **`None`** : ni égal à `0`, ni à `""` ; on le teste avec `is None`.

## 📝 Cellule 6 : Constantes

### 🔍 Avant d'exécuter

- **Constante** : une valeur qui ne doit pas changer (seuil, chemin, code). Python n'a pas de vraie constante : par **convention**, on écrit le nom en MAJUSCULES.
- **`Final`** : annotation qui signale « ne pas réaffecter ». Un **outil d'analyse** (Pylance, mypy) alerte, mais Python n'empêche rien.
- **Vraiment protégé** : un **tuple** (liste non modifiable) et `MappingProxyType` (dictionnaire en lecture seule) refusent toute modification.

### 💻 Code

```python
# === CELLULE 6 : Constantes, Final et MappingProxyType ===
from types import MappingProxyType
from typing import Final

# Une constante « par convention » : nom en MAJUSCULES, annotée « Final » pour les outils d'analyse
CAPACITE_MAX_MW: Final = 5.0

# Un tuple : une séquence qui ne peut pas être modifiée après sa création (parenthèses)
SITES_FLEXIBLES = ("SITE_IND_001", "SITE_IND_002", "SITE_RES_001", "SITE_RES_002")

# Un dictionnaire en lecture seule : associe un code d'erreur à sa signification
CODES_ERREUR = MappingProxyType({
    -999: "Capteur hors service",
    -888: "Valeur non transmise",
    -777: "Recalibrage en cours",
})

# Test 1 : réaffecter une constante « Final » -> Python l'accepte (seul un outil d'analyse protesterait)
CAPACITE_MAX_MW = 6.0
print(CAPACITE_MAX_MW)                    # 6.0

# Test 2 : modifier un dictionnaire en lecture seule -> Python refuse (TypeError)
try:
    CODES_ERREUR[-1] = "test"
except TypeError as erreur:
    print(f"Modification refusée : {erreur}")
```

### 📤 Résultat

```

```

### 💡 Interprétation

- **`6.0` s'affiche** : Python a accepté la réaffectation de `CAPACITE_MAX_MW`. Seul un vérificateur de types l'aurait signalée.
- **`CODES_ERREUR` refuse la modification** : la protection est **réelle** avec `MappingProxyType` (et les tuples).
- **Dans un notebook Fabric** : ces constantes forment la **cellule de configuration** en tête (noms de tables, chemins du Lakehouse, seuils métier).
- **Réutilisation** : `CODES_ERREUR` sera utilisé à plusieurs reprises dans la suite.

## 📝 Cellule 7 : Énumérations : `StrEnum`

### 🔍 Avant d'exécuter

- **Énumération** : un ensemble **fermé** de valeurs nommées. Ici, les deux statuts possibles d'une mesure : `OK` et `ERROR`.
- **Intérêt** : `Statut.OK` est plus sûr qu'un texte libre `"OK"` (une faute de frappe `"Ok"` passerait inaperçue).
- **Hier (avant 3.11)** : `class Statut(str, Enum)` ; `str(Statut.OK)` affiche alors `Statut.OK` (le nom de la classe).
- **Aujourd'hui (3.11+)** : `StrEnum` ; ses membres sont de **vraies chaînes** et `str(Statut.OK)` affiche `OK`.

### 💻 Code

```python
# === CELLULE 7 : StrEnum ===
from enum import Enum, StrEnum

# Hier : on combine « str » et « Enum » pour obtenir une énumération de textes
class StatutAncien(str, Enum):
    OK = "OK"
    ERROR = "ERROR"

# Aujourd'hui (Python 3.11+) : StrEnum fait la même chose en plus simple
class Statut(StrEnum):
    OK = "OK"            # le nom (OK) et la valeur ("OK") du membre
    ERROR = "ERROR"

print(str(StatutAncien.OK), "|", str(Statut.OK))     # StatutAncien.OK | OK : l'affichage diffère

# Un membre StrEnum est un vrai texte : on peut le comparer à une chaîne
print(Statut.OK == "OK")                             # True
print(Statut("ERROR") is Statut.ERROR)               # True : on retrouve un membre à partir de sa valeur

# Dans une f-string, on obtient directement le texte ; « [s.value for s in Statut] » liste les valeurs
print(f"{Statut.ERROR} / {[s.value for s in Statut]}")
```

### 📤 Résultat

```
StatutAncien.OK | OK
True
True
ERROR / ['OK', 'ERROR']
```

### 💡 Interprétation

- **Ancienne forme** : `str(StatutAncien.OK)` donne `StatutAncien.OK`.
- **`StrEnum`** : `str(Statut.OK)` donne `OK`, ce qui se prête mieux à l'affichage, aux fichiers et aux requêtes.
- **Comparaison** : `Statut.OK == "OK"` est vrai, on peut donc comparer avec les valeurs lues dans un CSV.
- **Compatibilité** : ✅ `StrEnum` existe dès Python 3.11, donc sur le Runtime Spark 1.3.

## 📝 Cellule 8 : Chaînes : découpage et méthodes

### 🔍 Avant d'exécuter

- **Chaîne** : une suite de caractères, **non modifiable** ; chaque méthode renvoie une **nouvelle** chaîne.
- **Découpage (*slicing*)** : `s[:8]` = les 8 premiers caractères ; `s[-3:]` = les 3 derniers ; `s[::-1]` = à l'envers.
- **Méthodes courantes** : `strip()` (retire les espaces aux extrémités), `split(",")` (coupe en liste), `replace(a, b)`, `lower()`, `startswith(...)`.
- **`removeprefix` / `removesuffix`** (3.9+) : retirent un début ou une fin **exacts**. À la différence de `lstrip`, qui retire des *caractères*.

### 💻 Code

```python
# === CELLULE 8 : Chaînes — découpage et méthodes ===

# Une ligne du fichier CSV, avec des espaces parasites au début et à la fin
ligne = "  2025-01-03T04:30:00,SITE_IND_002,0.865,234.6,49.89,OK  "

# strip() retire les espaces des extrémités ; split(",") coupe la ligne à chaque virgule -> une liste de 6 champs
champs = ligne.strip().split(",")
print(champs)

# Dépaquetage : 6 noms à gauche, 6 valeurs à droite, affectées dans l'ordre
timestamp, site_id, conso, tension, freq, statut = champs

# Découpage : [début:fin], avec une fin exclue ; les indices négatifs comptent depuis la fin
print(site_id[:8])       # SITE_IND : les 8 premiers caractères
print(site_id[-3:])      # 002      : les 3 derniers
print(site_id[::-1])     # 200_DNI_ETIS : le texte à l'envers

# Quelques méthodes : chacune renvoie une NOUVELLE chaîne (site_id n'est pas modifié)
print(site_id.lower())                    # site_ind_002
print(site_id.replace("_", "-"))          # SITE-IND-002
print(site_id.startswith("SITE_"))        # True
print(site_id.removeprefix("SITE_"))      # IND_002 : retire le début exact « SITE_ »
print(site_id.removesuffix("_002"))       # SITE_IND : retire la fin exacte « _002 »
```

### 📤 Résultat

```
['2025-01-03T04:30:00', 'SITE_IND_002', '0.865', '234.6', '49.89', 'OK']
SITE_IND
002
200_DNI_ETIS
site_ind_002
SITE-IND-002
True
IND_002
SITE_IND
```

### 💡 Interprétation

- **Immuable** : `site_id.lower()` ne change pas `site_id` ; il renvoie une copie.
- **`split(",")`** : transforme la ligne CSV en liste de 6 champs.
- **Dépaquetage** : `timestamp, site_id, ... = champs` affecte les six champs d'un coup ; c'est ce que fera `csv.DictReader` à la Cellule 41.
- **`removeprefix`** : retire exactement `SITE_` ; `lstrip("SITE_")` aurait retiré tous les caractères `S`, `I`, `T`, `E`, `_` en début de texte, ce qui est rarement voulu.

## 📝 Cellule 9 : Chaînes : trois générations de formatage

### 🔍 Avant d'exécuter

- **Formatage** : insérer des valeurs dans un texte (`"Site SITE_IND_001 : 2.50 MW"`).
- **Hier** : l'opérateur `%` (style « printf »), puis la méthode `.format()`.
- **Aujourd'hui** : la **f-string** (3.6+) : on préfixe le texte par `f` et on écrit les valeurs entre `{}`. `{mw=}` (3.8+) affiche aussi le nom, pratique pour déboguer.
- **Mini-langage** dans les `{}` : `:.2f` (2 décimales), `:,.2f` (milliers), `:.1%` (pourcentage), `:05d` (zéros devant), `:>15` (aligné à droite sur 15 caractères).

```python
# ❌ Python 2 — deux types de chaînes
texte = u"consommation électrique"     # unicode ; str = octets
# Python 3 : str = Unicode ; les octets s'écrivent b"..."
```

### 💻 Code

```python
# === CELLULE 9 : Chaînes — formatage ===
nom, mw = "SITE_IND_001", 2.5

# Trois écritures qui produisent le MÊME texte
print("Site %s : %.2f MW" % (nom, mw))            # Hier : « % » (%s = texte, %.2f = décimal à 2 chiffres)
print("Site {} : {:.2f} MW".format(nom, mw))      # Ensuite : .format(), les {} sont remplis dans l'ordre
print(f"Site {nom} : {mw:.2f} MW")                # Aujourd'hui : f-string, on écrit directement les variables

# {mw=} affiche « mw=2.5 » : le nom ET la valeur (idéal pour déboguer)
print(f"{mw=}")

# Le mini-langage de mise en forme, après les deux-points
print(f"{1234567.891:,.2f} | {0.0345:.1%} | {42:05d} | {nom:>15}")
#      milliers + 2 décimales | pourcentage | zéros devant | aligné à droite sur 15 caractères

# Chaîne « brute » : le préfixe r ignore les séquences d'échappement (\U, \f, \n...)
print(r"C:\Users\formation\data\consommation.csv")
```

### 📤 Résultat

```
Site SITE_IND_001 : 2.50 MW
Site SITE_IND_001 : 2.50 MW

```

### 💡 Interprétation

- **Trois lignes identiques** : seule l'écriture change ; préférer la **f-string**.
- **`{mw=}`** : donne `mw=2.5`, très utile pour déboguer sans réécrire le nom.
- **Mini-langage** : `1,234,567.89`, `3.5%` (0.0345 arrondi à 1 décimale), `00042`, et le nom aligné sur 15 caractères.

## 📝 Cellule 10 : Valeurs de vérité et comparaisons

### 🔍 Avant d'exécuter

- **Valeur de vérité** : Python sait dire, pour **n'importe quelle** valeur, si elle compte pour « vrai » ou pour « faux » dans un `if`.
- **Considérées comme fausses** : `0`, `0.0`, `""` (texte vide), `[]` (liste vide) et `None`. **Toutes les autres sont vraies**, y compris `"0"` (un texte non vide) et `-999`.
- **Comparaison chaînée** : `0 <= conso <= capacite` se lit comme en mathématiques, « conso est entre 0 et capacite ». C'est plus court que `conso >= 0 and conso <= capacite`.
- **`==` compare le contenu** : « ces deux valeurs sont-elles égales ? »
- **`is` compare l'identité** : « est-ce **le même objet** en mémoire ? » Deux listes `[1, 2]` créées séparément sont égales (`==`) sans être le même objet (`is`). On n'utilise `is` que pour `None`, `True` et `False`.

```python
# ❌ Python 2 — supprimés
if capacite <> 0: ...                      # utiliser !=
if dict_sites.has_key("SITE_IND_001"): ... # utiliser "SITE_IND_001" in dict_sites
```

### 💻 Code

```python
# === CELLULE 10 : Valeurs de vérité et comparaisons ===
conso, capacite = 0.865, 5.0             # deux variables créées en une ligne

# --- Comparaison chaînée : « conso est-elle comprise entre 0 et la capacité ? »
print(0 <= conso <= capacite)            # True

# --- Quelles valeurs sont « vraies » ou « fausses » ? bool(valeur) donne la réponse
valeurs = (0, 0.0, "", [], None, "0", -999)
print([bool(v) for v in valeurs])
# Résultat : les 5 premières sont False (0, 0.0, "", [], None) ; "0" et -999 sont True

# --- == (même contenu) contre is (même objet)
a = [1, 2]
b = [1, 2]                               # une AUTRE liste, qui contient la même chose
print(a == b)                            # True  : même contenu
print(a is b)                            # False : deux objets distincts en mémoire
print(a is not None)                     # True  : la façon correcte de tester « a n'est pas None »
```

### 📤 Résultat

```
True
[False, False, False, False, False, True, True]
True
False
True
```

### 💡 Interprétation

- **Liste de booléens** : `False, False, False, False, False, True, True` ; `"0"` et `-999` sont **vrais**.
- **Piège pour une mesure** : `if conso:` écarterait un capteur à zéro (valeur légitime) et laisserait passer `-999` (code d'erreur). Pour une mesure, on compare explicitement (`is None`, `>= 0`).
- **`a == b` est vrai, `a is b` est faux** : même contenu, objets différents.
- **`is`** : réservé à `None`, `True` et `False`.
- **Autres mondes** : la même logique de « valeur nulle » existe en pandas (`NaN`, `isna()`) et en SQL (`IS NULL`).

## 📝 Cellule 11 : Opérateurs logiques, `in` et opérateur morse

### 🔍 Avant d'exécuter

- **`and`, `or`, `not`** : combinent des conditions. `or` renvoie le **premier** opérande vrai : `statut or "INCONNU"` donne `"INCONNU"` si `statut` est faux (ici `None`).
- **`in`** : teste l'appartenance : un mot dans un texte (`"SITE" in "SITE_IND_001"`) ou une valeur dans une collection (`x in (1, 2, 3)`).
- **`:=` (« morse »)** (3.8+) : calcule une valeur, la **range dans une variable** et la teste, en une seule expression. Évite d'écrire le même calcul deux fois.

### 💻 Code

```python
# === CELLULE 11 : Opérateurs logiques, in et := ===

# --- « or » : valeur de repli. statut est None (faux), donc « or » renvoie le second opérande
statut = None
print(statut or "INCONNU")                       # INCONNU

# --- « in » : appartenance
print("SITE_IND" in "SITE_IND_001")              # True  : ce morceau de texte est dans le texte
print(conso in (-999, -888, -777))               # False : 0.865 n'est pas un code d'erreur

# --- « := » : calculer et garder le résultat dans la même expression
mesures = ["0.865", "abc", "1.2"]
# Sans « := », on écrirait : n = len(mesures) puis, sur la ligne suivante, if n > 2:
if (n := len(mesures)) > 2:                      # len(mesures) est calculé UNE fois, rangé dans n, puis comparé à 2
    print(f"{n} mesures reçues")                 # n est utilisable ici
```

### 📤 Résultat

```
INCONNU
True
False
3 mesures reçues
```

### 💡 Interprétation

- **`statut or "INCONNU"`** : donne `INCONNU` car `None` est faux.
- **Attention** : `or` remplace aussi `0` et `""`. À utiliser quand ces valeurs sont invalides, pas quand elles sont légitimes.
- **`in`** : `"SITE_IND" in "SITE_IND_001"` est vrai ; `0.865 in (-999, -888, -777)` est faux.
- **`:=`** : `len(mesures)` est calculé une seule fois ; `n` reste disponible après le `if`.
- **Usage typique** : boucles de lecture et compréhensions, où le même calcul serait sinon répété.

## 📝 Cellule 12 : Conditions : `if` / `elif` / `else`

### 🔍 Avant d'exécuter

- **`if` / `elif` / `else`** : Python teste les conditions **dans l'ordre** ; la première qui est vraie l'emporte, les suivantes ne sont pas évaluées. `else` couvre tous les autres cas.
- **Ternaire** : `a if condition else b` choisit une valeur sur **une seule ligne** (ex. `"flexible" if ... else "rigide"`).
- **Dictionnaire** : associe une clé à une valeur ; `.items()` le parcourt en donnant clé **et** valeur.
- **Ici** : on compare la mesure d'un site à sa capacité (le **taux de charge**) et on classe le résultat.

### 💻 Code

```python
# === CELLULE 12 : Conditions ===

# Deux dictionnaires : capacité de chaque site, et une mesure en MW
capacites = {"SITE_IND_001": 5.0, "SITE_COM_002": 1.5, "SITE_RES_002": 0.6}
mesures = {"SITE_IND_001": 4.6, "SITE_COM_002": 0.4, "SITE_RES_002": 0.61}

# .items() donne, à chaque tour, une clé (le site) et sa valeur (la capacité)
for site_id, capacite in capacites.items():
    taux = mesures[site_id] / capacite          # taux de charge : 1.0 = 100 % de la capacité

    # Les tests sont évalués dans l'ordre : le premier qui est vrai décide.
    if taux > 1:                                # d'abord le cas impossible : la mesure dépasse la capacité
        niveau = "ANOMALIE (dépasse la capacité)"
    elif taux >= 0.8:                           # sinon, très chargé
        niveau = "CRITIQUE"
    elif taux >= 0.5:                           # sinon, chargé
        niveau = "SOUTENU"
    else:                                       # tous les autres cas
        niveau = "NORMAL"

    # Ternaire : « valeur_si_vrai if condition else valeur_si_faux ».
    # startswith accepte un TUPLE de préfixes : vrai si le texte commence par l'un d'eux.
    profil = "flexible" if site_id.startswith(("SITE_IND", "SITE_RES")) else "rigide"

    print(f"{site_id} : {taux:6.1%} -> {niveau:<32} ({profil})")
```

### 📤 Résultat

```
SITE_IND_001 :  92.0% -> CRITIQUE                         (flexible)
SITE_COM_002 :  26.7% -> NORMAL                           (rigide)
SITE_RES_002 : 101.7% -> ANOMALIE (dépasse la capacité)   (flexible)
```

### 💡 Interprétation

- **`SITE_RES_002` dépasse sa capacité** : `0.61 > 0.6`, donc `ANOMALIE`.
- **Ordre des tests** : `taux > 1` doit venir **en premier**. Placé après `>= 0.8`, il aurait été masqué par `CRITIQUE` : l'ordre fait partie de la logique métier.
- **Ternaire** : `profil` prend `flexible` ou `rigide` en une seule ligne.
- **`startswith((...))`** : le tuple évite d'écrire `... or ...`.

## 📝 Cellule 13 : `match` / `case` : hier et aujourd'hui

### 🔍 Avant d'exécuter

- **Objectif** : interpréter un code de mesure (valide, manquant, code d'erreur…).
- **Hier** : une chaîne de `if` / `elif` qui répète `code ==` à chaque ligne.
- **Aujourd'hui (3.10+)** : `match` / `case`, un filtrage par **motifs**. On lit chaque `case` comme une ligne d'une table de décision.
- **Trois outils** : `case _` = « tout le reste » ; `|` = « ou » entre deux motifs ; `if` après un motif = condition supplémentaire (une **garde**).

### 💻 Code

```python
# === CELLULE 13 : match / case ===

# Hier : une chaîne de if / elif, où « code » est répété à chaque ligne
def decrire_ancien(code):
    if code is None or code == "":
        return "valeur manquante"
    elif code == -999:
        return "capteur hors service"
    elif code == -888 or code == -777:
        return "valeur non transmise ou recalibrage"
    elif isinstance(code, (int, float)) and code >= 0:
        return "mesure valide"
    else:
        return "valeur inattendue"

# Aujourd'hui (3.10+) : match / case. Python compare « code » à chaque motif, de haut en bas.
def decrire(code):
    match code:
        case None | "":                       # « | » : ce motif OU celui-là
            return "valeur manquante"
        case -999:                            # un motif peut être une valeur littérale
            return "capteur hors service"
        case -888 | -777:
            return "valeur non transmise ou recalibrage"
        case int() | float() if code >= 0:    # int() : « est un entier » ; « if » : garde supplémentaire
            return "mesure valide"
        case _:                               # « _ » : tous les autres cas (comme else)
            return "valeur inattendue"

# On vérifie que les deux versions donnent le même résultat sur six valeurs
for valeur in (0.865, -999, -888, None, "", "abc"):
    print(f"{valeur!r:>8} -> {decrire(valeur):<38} identique : {decrire(valeur) == decrire_ancien(valeur)}")
```

### 📤 Résultat

```
   0.865 -> mesure valide                          identique : True
    -999 -> capteur hors service                   identique : True
    -888 -> valeur non transmise ou recalibrage    identique : True
    None -> valeur manquante                       identique : True
      '' -> valeur manquante                       identique : True
   'abc' -> valeur inattendue                      identique : True
```

### 💡 Interprétation

- **Résultats** : `0.865` → mesure valide, `-999` → capteur hors service, `-888` → non transmise, `None` et `""` → manquante, `"abc"` → inattendue.
- **`identique : True`** sur toutes les lignes : les deux versions se comportent pareil.
- **Lisibilité** : la version `match` se lit comme une table de décision, sans répéter `code ==`.
- **Compatibilité** : ✅ Python 3.10+, donc tous les runtimes Fabric actuels.

## 📝 Cellule 14 : `match` sur un dictionnaire

### 🔍 Avant d'exécuter

- **Enregistrement** : une ligne de données sous forme de dictionnaire, par exemple `{"status": "OK", "consumption_mw": 1.224}`.
- **Motif de dictionnaire** : `case {"status": "OK", ...}` réussit si ces clés existent avec ces valeurs.
- **Capture** : `"consumption_mw": code` **range** la valeur trouvée dans une variable `code`, utilisable dans le `case`.
- **Usage** : trier des enregistrements JSON, CSV ou des messages d'API selon leur forme.

### 💻 Code

```python
# === CELLULE 14 : match sur un enregistrement ===
def traiter(enregistrement):
    match enregistrement:
        # Cas 1 : statut ERROR ET une clé consumption_mw, dont la valeur est capturée dans « code »
        #         (la garde « if » vérifie que c'est un code connu de CODES_ERREUR)
        case {"status": "ERROR", "consumption_mw": code} if code in CODES_ERREUR:
            return f"rejet : {CODES_ERREUR[code]}"
        # Cas 2 : statut OK ET une valeur décimale (float), capturée dans « valeur »
        case {"status": "OK", "consumption_mw": float(valeur)}:
            return f"accepté : {valeur} MW"
        # Cas 3 : tout le reste
        case _:
            return "à examiner"

print(traiter({"status": "ERROR", "consumption_mw": -999}))   # cas 1
print(traiter({"status": "OK", "consumption_mw": 1.224}))     # cas 2
print(traiter({"status": "OK"}))                              # cas 3 : la clé consumption_mw manque
```

### 📤 Résultat

```
rejet : Capteur hors service
accepté : 1.224 MW
à examiner
```

### 💡 Interprétation

- **Premier appel** : `rejet : Capteur hors service` (motif 1, avec `code = -999`).
- **Deuxième appel** : `accepté : 1.224 MW` (motif 2, avec `valeur = 1.224`).
- **Troisième appel** : la clé `consumption_mw` manque ; l'enregistrement tombe dans `case _` **sans erreur** (avec `traiter["consumption_mw"]`, on aurait eu un `KeyError`).
- **Usage** : adapté aux messages JSON de structure variable (événements, API).

## 📝 Cellule 15 : Boucles `for` : `enumerate` et `zip`

### 🔍 Avant d'exécuter

- **Boucle `for`** : répète un bloc pour chaque élément d'une séquence.
- **`enumerate(seq, start=1)`** : donne **le numéro et l'élément** à chaque tour (numérotation à partir de 1 avec `start=1`).
- **`zip(a, b)`** : parcourt **deux séquences en parallèle** (le 1er de `a` avec le 1er de `b`, etc.).

### 💻 Code

```python
# === CELLULE 15 : for, enumerate, zip ===
sites = ["SITE_IND_001", "SITE_IND_002", "SITE_COM_001",
         "SITE_COM_002", "SITE_RES_001", "SITE_RES_002"]

# enumerate : (numéro, élément) à chaque tour ; start=1 pour compter à partir de 1
for rang, site in enumerate(sites, start=1):
    print(rang, site)

# zip : on lit « sites » et « capacites_mw » en parallèle
for site, cap in zip(sites, capacites_mw):
    print(f"{site} : {cap} MW")
```

```

3 SITE_COM_001
4 SITE_COM_002

6 SITE_RES_002
SITE_IND_001 : 5.0 MW
SITE_IND_002 : 3.5 MW
SITE_COM_001 : 2.0 MW
SITE_COM_002 : 1.5 MW
SITE_RES_001 : 0.8 MW
SITE_RES_002 : 0.6 MW
```

### 💡 Interprétation

- **`enumerate`** : affiche `1 SITE_IND_001` … `6 SITE_RES_002`, sans gérer d'indice à la main.
- **`zip`** : associe chaque site à sa capacité (`SITE_IND_001 : 5.0 MW`, …).

- **Réutilisation** : les listes `sites` et `capacites_mw` servent dans la suite.

## 📝 Cellule 16 : `zip` paresseux et `strict=True`

### 🔍 Avant d'exécuter

- **Paresseux** : en Python 3, `zip(...)` ne construit pas de liste ; il renvoie un **itérateur** qui produit les paires **au fur et à mesure**. Pour voir le contenu, on l'enveloppe dans `list(...)`.
- **Sans `strict`** : si les deux séquences n'ont pas la même longueur, `zip` s'arrête **en silence** à la plus courte.
- **`strict=True`** (3.10+) : lève une erreur (`ValueError`) si les longueurs diffèrent.

```python
# ❌ Python 2 — zip() construisait directement une liste
paires = zip(sites, capacites)
print paires[0]                  # fonctionnait ; TypeError en Python 3 (objet non indexable)
```

### 💻 Code

```python
# === CELLULE 16 : zip paresseux et strict ===
paires = zip(sites, capacites_mw)
print(paires)                           # <zip object ...> : un itérateur, pas une liste
print(list(paires)[:2])                 # list(...) le consomme : les 2 premières paires

# Sans strict : listes de longueurs différentes (6 sites, 4 capacités) -> aucune erreur
print(len(list(zip(sites, capacites_mw[:4]))))     # 4 : deux sites disparaissent en silence

# Avec strict=True : la différence de longueur est détectée
try:
    list(zip(sites, capacites_mw[:4], strict=True))
except ValueError as erreur:
    print(f"ValueError : {erreur}")
```

### 📤 Résultat

```
<zip object at 0x000001F3A2B4C8C0>
[('SITE_IND_001', 5.0), ('SITE_IND_002', 3.5)]
4
ValueError : zip() argument 2 is shorter than argument 1
```

### 💡 Interprétation

- **`<zip object ...>`** : la première ligne montre un itérateur, pas les données.
- **Sans `strict`** : 6 sites deviennent 4 sans aucun message ; un capteur oublié disparaît.
- **Avec `strict=True`** : l'incohérence est **détectée immédiatement** (`ValueError`).
- **Bonne pratique** : `strict=True` par défaut quand les longueurs **doivent** correspondre.

## 📝 Cellule 17 : `break`, `continue`, `else` de boucle, `while`

### 🔍 Avant d'exécuter

- **`continue`** : saute le reste du tour et passe à l'élément suivant.
- **`break`** : quitte la boucle immédiatement.
- **`for ... else`** : le `else` ne s'exécute que si la boucle est allée **jusqu'au bout sans `break`**. Il exprime « aucun élément n'a répondu au critère ».
- **`while`** : répète tant qu'une condition reste vraie.

### 💻 Code

```python
# === CELLULE 17 : break, continue, else, while ===

# On cherche le premier site de plus de 3 MW, en ignorant les sites de moins de 1 MW
for site, cap in zip(sites, capacites_mw):
    if cap < 1.0:
        continue                                # site trop petit : on passe au suivant
    if cap > 3.0:
        print(f"Premier site > 3 MW : {site}")
        break                                   # trouvé : on quitte la boucle (le « else » ci-dessous est alors sauté)
else:
    print("Aucun site > 3 MW")                  # atteint seulement si la boucle n'a jamais fait « break »

# while : on répète tant que le cumul est inférieur à 10 MWh
cumul_mwh, heure = 0.0, 0
while cumul_mwh < 10:
    cumul_mwh += 2.5                            # +2.5 MWh à chaque heure
    heure += 1
print(f"{cumul_mwh} MWh atteints après {heure} h")
```

### 📤 Résultat

```
Premier site > 3 MW : SITE_IND_001
10.0 MWh atteints après 4 h
```

### 💡 Interprétation

- **Premier tour** : `SITE_IND_001` (5.0 MW) dépasse 3 MW ; la boucle s'arrête (`break`) et le `else` n'est pas exécuté.
- **`for ... else`** : évite une variable « trouvé = True » ; utile pour dire « rien trouvé ».
- **`while`** : le cumul passe par 2.5, 5.0, 7.5, 10.0 ; quatre tours, 4 h.
- **Danger** : si la condition d'un `while` ne devient jamais fausse, la cellule tourne sans fin (menu **Kernel → Interrupt**).

## 📝 Cellule 18 : Compréhensions de liste

### 🔍 Avant d'exécuter

- **Définition** : une **compréhension de liste** construit une **nouvelle liste** à partir d'une autre, en **filtrant** et/ou en **transformant** les éléments, en une seule ligne.
- **Syntaxe** : `[ ce_qu_on_garde   for élément in source   if condition ]`. Le `if` est facultatif.
- **Exemple sans compréhension** : 4 lignes (créer une liste vide, boucler, tester, ajouter).
- **Exemple avec** : 1 ligne, même résultat.

```python
capacites = [5.0, 1.5, 3.5, 0.6]

# Sans compréhension : garder les capacités supérieures à 2 MW
grands = []                      # 1. liste vide
for cap in capacites:            # 2. on parcourt
    if cap > 2:                  # 3. on filtre
        grands.append(cap)       # 4. on ajoute
# grands vaut [5.0, 3.5]

# Avec compréhension : le même résultat
grands = [cap for cap in capacites if cap > 2]     # [5.0, 3.5]
```

- **Dans la cellule** : la même idée sert à **filtrer des mesures**. On garde uniquement les nombres décimaux positifs et on écarte le code `-999` et le texte vide.

### 💻 Code

```python
# === CELLULE 18 : Compréhensions de liste ===

# Des mesures brutes mélangées : décimaux, codes d'erreur (entiers) et texte vide
mesures_brutes = [0.865, -999, 1.224, "", 0.149, -888, 1.105]

# --- Sans compréhension (4 lignes)
valides = []                                            # 1. on crée une liste vide
for m in mesures_brutes:                                # 2. on parcourt les mesures
    if isinstance(m, float) and m >= 0:                 # 3. on garde les décimaux positifs (isinstance teste le type)
        valides.append(m)                               # 4. on ajoute à la liste

# --- Avec compréhension (1 ligne) : « m pour chaque m de mesures_brutes, si la condition est vraie »
valides = [m for m in mesures_brutes if isinstance(m, float) and m >= 0]
print(valides)                                          # [0.865, 1.224, 0.149, 1.105]
```

### 📤 Résultat

```
[0.865, 1.224, 0.149, 1.105]
```

### 💡 Interprétation

- **Résultat** : `[0.865, 1.224, 0.149, 1.105]` avec les deux écritures.
- **Pourquoi `-999` est écarté** : c'est un `int`, pas un `float`, donc `isinstance(m, float)` est faux. Le texte vide `""` l'est aussi.
- **Bénéfice** : filtrer, transformer et construire la liste tiennent en **une ligne**.
- **Limite** : au-delà de deux lignes ou d'une logique compliquée, une boucle classique reste plus lisible.

## 📝 Cellule 19 : Compréhensions de dictionnaire et d'ensemble

### 🔍 Avant d'exécuter

- **Dictionnaire** : `{clé: valeur for ... in ...}` construit un dictionnaire. Ici, un site → sa capacité.
- **Ensemble (`set`)** : `{valeur for ... in ...}` (une seule valeur entre accolades, pas de `:`) construit un ensemble : collection **sans doublon et sans ordre**.
- **Exemple** : `{s.split("_")[1] for s in sites}` garde le **2ᵉ morceau** de chaque identifiant (`IND`, `COM`, `RES`). Chaque famille n'apparaît **qu'une fois**, même si elle est présente sur deux sites.

### 💻 Code

```python
# === CELLULE 19 : Dictionnaires et ensembles par compréhension ===

# Dictionnaire : pour chaque couple (site, capacité) de zip, on crée « site: capacité »
capacite_par_site = {s: c for s, c in zip(sites, capacites_mw)}
print(capacite_par_site["SITE_COM_001"])           # 2.0 : on retrouve une capacité à partir du site

# Ensemble : « SITE_IND_001 ».split("_") donne ["SITE", "IND", "001"] ; [1] prend "IND"
familles = {s.split("_")[1] for s in sites}        # 6 sites, mais seulement 3 familles distinctes
print(sorted(familles))                            # sorted(...) : un ensemble n'a pas d'ordre, on trie pour l'affichage
```

### 📤 Résultat

```
2.0
['COM', 'IND', 'RES']
```

### 💡 Interprétation

- **`capacite_par_site["SITE_COM_001"]`** : `2.0`. Un dictionnaire retrouve une valeur à partir de sa clé, sans parcourir de liste.
- **Familles** : `['COM', 'IND', 'RES']` ; les six sites donnent trois valeurs, car un ensemble **élimine les doublons**.
- **Équivalent pandas** : `df["site_id"].unique()` joue le même rôle.

## 📝 Cellule 20 : Générateurs : calculer à la demande

### 🔍 Avant d'exécuter

- **Problème** : une liste stocke **tous** ses éléments en mémoire. Pour un fichier de plusieurs Go, c'est impossible.
- **Générateur** : un objet qui **produit les valeurs une par une, à la demande**, sans jamais construire la liste entière. On l'écrit comme une compréhension, mais avec des **parenthèses** : `(x for x in ...)`.
- **`next(gen)`** : demande la valeur suivante.
- **Un seul passage** : une fois épuisé, un générateur est vide.

### 💻 Code

```python
# === CELLULE 20 : Générateurs ===

# Avec des parenthèses : rien n'est calculé pour l'instant
gen = (m * 1000 for m in valides)         # les mesures (MW) converties en kW, une par une, à la demande
print(type(gen).__name__)                 # generator : ce n'est pas une liste
print(next(gen))                          # calcule et donne la 1re valeur : 865.0
print(next(gen))                          # la 2e : 1224.0

# Le reste du générateur : list() demande toutes les valeurs restantes
print(list(gen))                          # [149.0, 1105.0] : les deux premières ont déjà été consommées
print(list(gen))                          # [] : un générateur épuisé est vide

# sum() accepte directement un générateur : la somme se calcule sans créer de liste
print(sum(m for m in valides))            # 3.343
```

### 📤 Résultat

```
generator
865.0
1224.0
[149.0, 1105.0]
[]
3.343
```

### 💡 Interprétation

- **`generator`** : un objet paresseux ; `next` déclenche **un** calcul à la fois.
- **Épuisement** : après avoir consommé 2 valeurs, `list(gen)` donne les 2 restantes, puis `[]`.
- **`sum(m for m in valides)`** : somme sans liste intermédiaire.
- **Application** : la fonction `lire_csv` (Partie 6) est un générateur : elle lit un fichier de plusieurs Go **ligne par ligne**, sans le charger entièrement.

## 📝 Cellule 21 : Un objet qui se comporte comme une liste : `__len__`, `__getitem__`, `__iter__`, `__contains__`

### 🔍 Avant d'exécuter

- **Classe** : un **plan de fabrication** d'objets. `self` désigne l'objet en cours ; `__init__` s'exécute à la création (`ParcSites([...])`).
- **Méthode magique** : une méthode dont le nom est entouré de `__` (`__len__`…). **Python l'appelle tout seul** quand on utilise une syntaxe : `len(x)` appelle `x.__len__()`, `x[0]` appelle `x.__getitem__(0)`, `for a in x` appelle `x.__iter__()`, `a in x` appelle `x.__contains__(a)`.
- **`__repr__`** : le texte que le notebook affiche pour l'objet.
- **Pourquoi c'est utile pour Fabric** : un **DataFrame** fonctionne ainsi : `len(df)`, `df["colonne"]`, `for colonne in df`, `"colonne" in df`. Ici, on fabrique la même mécanique en petit.

### 💻 Code

```python
# === CELLULE 21 : Méthodes magiques d'une collection ===
class ParcSites:
    """Un parc de sites qui se comporte comme une collection Python."""

    def __init__(self, identifiants):         # appelée à la création : ParcSites(liste)
        self._sites = list(identifiants)      # on garde les identifiants dans une liste interne

    def __repr__(self):                       # __repr__ : ce que le notebook affiche pour l'objet
        return f"ParcSites({len(self._sites)} sites)"

    def __len__(self):                        # __len__ : appelée par len(parc)
        return len(self._sites)

    def __getitem__(self, position):          # __getitem__ : appelée par parc[0], parc[-1], parc[1:3]
        return self._sites[position]

    def __iter__(self):                       # __iter__ : appelée par « for site in parc »
        return iter(self._sites)

    def __contains__(self, site_id):          # __contains__ : appelée par « "SITE_X" in parc »
        return site_id in self._sites

parc = ParcSites(sites)                       # « sites » : la liste de six identifiants de la Cellule 15
print(parc)                                   # __repr__ : ParcSites(6 sites)
print(len(parc))                              # __len__ : 6
print(parc[0], "|", parc[-1], "|", parc[1:3]) # __getitem__ : un élément, le dernier, une tranche
print("SITE_COM_001" in parc, "SITE_XXX" in parc)   # __contains__ : True False
print([s for s in parc if s.startswith("SITE_RES")])   # __iter__ : parcours avec une compréhension
```

### 📤 Résultat

```
ParcSites(6 sites)
6
SITE_IND_001 | SITE_RES_002 | ['SITE_IND_002', 'SITE_COM_001']
True False
['SITE_RES_001', 'SITE_RES_002']
```

### 💡 Interprétation

- **`ParcSites(6 sites)`** : c'est `__repr__` qui produit ce texte ; sans lui, on verrait une adresse mémoire illisible.
- **`len(parc)` = 6**, **`parc[0]`** = premier site, **`parc[1:3]`** = une tranche : les crochets fonctionnent parce que `__getitem__` existe.
- **`in`** : `"SITE_COM_001" in parc` est vrai, `"SITE_XXX" in parc` est faux.
- **`for`** : la compréhension parcourt le parc grâce à `__iter__`.
- **Lien avec pandas** : `df["colonne"]`, `len(df)`, `for c in df`, `"c" in df` reposent sur ces mêmes quatre méthodes.

## 📝 Cellule 22 : Définir une fonction, documenter, retourner

### 🔍 Avant d'exécuter

- **Fonction** : un bloc de code **nommé**, qu'on écrit une fois et qu'on appelle autant de fois qu'on veut.
- **`def nom(paramètres):`** : définit la fonction ; le corps est **indenté**.
- **`return`** : renvoie le résultat. Sans `return`, la fonction renvoie `None`.
- **Docstring** : la première chaîne entre `"""` documente la fonction ; `help()` et les éditeurs l'affichent.
- **Plusieurs résultats** : `return a, b, c` renvoie **un tuple**, qu'on peut déballer en trois variables.

### 💻 Code

```python
# === CELLULE 22 : Fonctions ===
def taux_charge(conso_mw, capacite_mw):
    """Retourne le taux de charge d'un site (1.0 = 100 % de la capacité)."""   # docstring
    return conso_mw / capacite_mw                       # return : le résultat renvoyé à l'appelant

def statistiques(valeurs):
    """Retourne (minimum, maximum, moyenne) : un tuple de trois valeurs."""
    return min(valeurs), max(valeurs), sum(valeurs) / len(valeurs)

print(taux_charge(2.5, 5.0))                            # 0.5 : appel avec deux arguments
print(taux_charge.__doc__)                              # la docstring est conservée dans l'objet fonction

# « valides » vient de la Cellule 18 ; on déballe le tuple en trois variables
mini, maxi, moyenne = statistiques(valides)
print(mini, maxi, round(moyenne, 3))                    # round(x, 3) : arrondi à 3 décimales
```

### 📤 Résultat

```
0.5
Retourne le taux de charge d'un site (1.0 = 100 % de la capacité).
0.149 1.224 0.836
```

### 💡 Interprétation

- **`0.5`** : 2,5 MW sur 5 MW = 50 % de la capacité.
- **Docstring** : conservée dans `taux_charge.__doc__`.
- **Tuple** : `mini, maxi, moyenne = ...` déconstruit le résultat en trois variables.
- **Réutilisation** : les fonctions de qualité de données des parties suivantes suivent le même modèle.

## 📝 Cellule 23 : Paramètres nommés et valeurs par défaut

### 🔍 Avant d'exécuter

- **Paramètre par défaut** : `arrondi=3` vaut `3` si l'appelant ne le précise pas.
- **Arguments nommés** : `f(capacite_mw=2.0, valeur=3.0)` : l'ordre n'a plus d'importance.
- **`*` dans la définition** : ce qui suit doit être **nommé** à l'appel.
- **`/` dans la définition** (3.8+) : ce qui précède doit être **positionnel** (pas nommé).

### 💻 Code

```python
# === CELLULE 23 : Paramètres ===

# « valeur » et « capacite_mw » sont libres ; « arrondi » et « plafond » viennent APRÈS le « * » :
# ils doivent obligatoirement être nommés à l'appel, et ils ont une valeur par défaut.
def normaliser(valeur, capacite_mw, *, arrondi=3, plafond=1.0):
    return round(min(valeur / capacite_mw, plafond), arrondi)   # min(...) plafonne le résultat

print(normaliser(1.224, 2.0))                                   # défauts : arrondi=3, plafond=1.0
print(normaliser(capacite_mw=2.0, valeur=3.0, plafond=0.95))    # nommés, dans un autre ordre

try:
    normaliser(1.224, 2.0, 1)       # ambigu : que représente « 1 » ? Python refuse
except TypeError as erreur:
    print(f"TypeError : {erreur}")

# « / » : conso_mw doit être passé par POSITION ; capacite_mw peut être nommé
def classer(conso_mw, /, capacite_mw):
    return "critique" if conso_mw / capacite_mw >= 0.8 else "normal"

print(classer(1.7, capacite_mw=2.0))                            # critique (1.7 / 2.0 = 85 %)
```

### 📤 Résultat

```
0.612
0.95
TypeError : normaliser() takes 2 positional arguments but 3 were given
critique
```

### 💡 Interprétation

- **`0.612`** : 1,224 / 2,0 arrondi à 3 décimales.
- **`0.95`** : le résultat 1,5 est **plafonné** à 0,95.
- **`TypeError`** : `normaliser(1.224, 2.0, 1)` est ambigu, donc interdit grâce au `*`.
- **Écosystème** : `pd.read_csv(chemin, sep=";", encoding="utf-8")` suit le même principe (options nommées).

## 📝 Cellule 24 : Piège : valeur par défaut mutable

### 🔍 Avant d'exécuter

- **Piège** : la valeur par défaut est créée **une seule fois**, quand `def` est exécuté, pas à chaque appel.
- **Conséquence** : une liste `[]` par défaut est **partagée** entre tous les appels.
- **Remède** : `None` par défaut, puis création de la liste dans le corps.
- **Dans un notebook** : le bug s'aggrave, car on ré-exécute souvent les cellules.

### 💻 Code

```python
# === CELLULE 24 : Valeur par défaut mutable ===

# ❌ Version piégée : « historique=[] » est créée UNE fois et réutilisée à chaque appel
def enregistrer_erreur_piege(code, historique=[]):
    historique.append(code)
    return historique

print(enregistrer_erreur_piege(-999))     # [-999]
print(enregistrer_erreur_piege(-888))     # on attend [-888] ; on obtient [-999, -888]

# ✅ Version correcte : None par défaut, la liste est créée à chaque appel
def enregistrer_erreur(code, historique=None):
    if historique is None:                # aucun historique fourni : on en crée un neuf
        historique = []
    historique.append(code)
    return historique

print(enregistrer_erreur(-999), enregistrer_erreur(-888))   # [-999] [-888]
```

### 📤 Résultat

```
[-999]
[-999, -888]
[-999] [-888]
```

### 💡 Interprétation

- **Version piégée** : le second appel renvoie `[-999, -888]` : l'historique de l'appel précédent a fui.
- **Version corrigée** : chaque appel repart d'une liste neuve.
- **Règle** : jamais de `[]`, `{}` ou `set()` comme valeur par défaut ; utiliser `None`.

## 📝 Cellule 25 : `*args`, `**kwargs` et dépaquetage

### 🔍 Avant d'exécuter

- **`*args`** : ramasse un nombre **variable** d'arguments positionnels dans un tuple.
- **`**kwargs`** : ramasse des arguments **nommés** quelconques dans un dictionnaire.
- **`*` / `**` à l'appel** : dépaquètent une liste ou un dictionnaire en arguments séparés.
- **`a, *milieu, z = seq`** : prend le premier, le dernier, et met le reste dans une liste.

### 💻 Code

```python
# === CELLULE 25 : *args, **kwargs, dépaquetage ===

# *consos : autant de valeurs que l'on veut ; elles arrivent dans un tuple « consos »
def moyenne_sites(*consos, ignorer=()):
    retenues = [c for c in consos if c not in ignorer]     # on écarte les valeurs à ignorer
    return sum(retenues) / len(retenues)

print(moyenne_sites(0.865, 1.224, -999, ignorer=(-999,)))  # 1.0445 : le -999 est ignoré

# **options : tous les arguments nommés arrivent dans le dictionnaire « options »
def config_lecture(chemin, **options):
    return {"chemin": chemin, **options}                   # ** réinjecte le dictionnaire

options = {"encoding": "utf-8-sig", "sep": ","}
print(config_lecture("data/consommation_echantillon.csv", **options))   # ** à l'appel : un dict devient des arguments nommés

# Déballage étoilé : premier, dernier, et le reste au milieu
premier, *milieu, dernier = sites
print(premier, len(milieu), dernier)                       # SITE_IND_001 4 SITE_RES_002
```

### 📤 Résultat

```

{'chemin': 'data/consommation_echantillon.csv', 'encoding': 'utf-8-sig', 'sep': ','}

```

### 💡 Interprétation

- **`moyenne_sites`** : accepte 3 valeurs ou 30 ; `-999` est écarté.
- **`config_lecture`** : accepte n'importe quelle option et la transmet ; c'est ce que font `pandas.read_csv` et `spark.read.options(...)`.
- **`premier, *milieu, dernier`** : isole les extrémités d'une séquence (`milieu` contient les 4 autres).

## 📝 Cellule 26 : Fusion de dictionnaires : `{**a, **b}` et `|`

### 🔍 Avant d'exécuter

- **Fusionner** : combiner deux dictionnaires en un seul. Si une clé existe dans les deux, la valeur du **second** l'emporte.
- **Exemple concret** : des options de lecture **par défaut** (`sep=","`), que l'utilisateur veut **surcharger** (`sep=";"`) sans les réécrire toutes.
- **Hier (3.5+)** : `{**defauts, **perso}` : chaque `**` « déverse » un dictionnaire dans un nouveau.
- **Aujourd'hui (3.9+)** : `defauts | perso`, qui se lit comme une addition.

### 💻 Code

```python
# === CELLULE 26 : Fusion de dictionnaires ===

# Les options par défaut, et la surcharge de l'utilisateur (une seule clé change)
defauts = {"encoding": "utf-8-sig", "sep": ","}
perso = {"sep": ";"}

# Hier : chaque ** déverse un dictionnaire dans un nouveau ; la clé « sep » de « perso » écrase l'ancienne
print({**defauts, **perso})       # {'encoding': 'utf-8-sig', 'sep': ';'}

# Aujourd'hui (3.9+) : l'opérateur | fait la même chose, plus lisiblement
print(defauts | perso)            # {'encoding': 'utf-8-sig', 'sep': ';'}

# Les deux écritures donnent le même résultat ; « defauts » n'a pas été modifié
print((defauts | perso) == {**defauts, **perso})   # True
print(defauts)                                     # {'encoding': 'utf-8-sig', 'sep': ','}
```

### 📤 Résultat

```
{'encoding': 'utf-8-sig', 'sep': ';'}
{'encoding': 'utf-8-sig', 'sep': ';'}
True
{'encoding': 'utf-8-sig', 'sep': ','}
```

### 💡 Interprétation

- **Résultat** : `encoding` est conservé, `sep` devient `;` : la valeur de `perso` l'emporte.
- **`defauts` reste intact** : la fusion crée un **nouveau** dictionnaire.
- **`|`** : plus lisible que `{**a, **b}` ; disponible depuis Python 3.9.
- **Fabric** : même principe pour fusionner les paramètres par défaut d'un notebook avec ceux transmis par un pipeline.

## 📝 Cellule 27 : Annotations de types

### 🔍 Avant d'exécuter

- **Annotation** : une indication du type attendu (`valeurs: list[float]`) et du type rendu (`-> float | None`).
- **Hier (3.5–3.8)** : `List[float]`, `Optional[float]` importés depuis `typing`.
- **Aujourd'hui (3.10+)** : `list[float]` et `float | None`, sans import.
- **Important** : Python **n'impose rien** à l'exécution. Les annotations servent aux lecteurs et aux éditeurs.

### 💻 Code

```python
# === CELLULE 27 : Annotations de types ===
from typing import List, Optional

# Hier : il fallait importer List et Optional
def moyenne_v1(valeurs: List[float]) -> Optional[float]:
    return sum(valeurs) / len(valeurs) if valeurs else None    # None si la liste est vide

# Aujourd'hui : « float | None » se lit « un float ou None »
def moyenne_v2(valeurs: list[float]) -> float | None:
    return sum(valeurs) / len(valeurs) if valeurs else None

print(moyenne_v2.__annotations__)              # les annotations sont stockées, sans être vérifiées
print(moyenne_v1([]), moyenne_v2([1.0, 2.0]))  # None 1.5
print(moyenne_v2([1, 2, 3]))                   # des int alors que l'annotation annonce des float : 2.0, aucune erreur
```

### 📤 Résultat

```
{'valeurs': list[float], 'return': float | None}
None 1.5
2.0
```

### 💡 Interprétation

- **Dernier appel** : passe des `int` alors que l'annotation annonce des `float` ; aucune erreur.
- **Rôle** : documenter et outiller (auto-complétion, détection d'erreurs par l'éditeur), pas contrôler.
- **Compatibilité** : ✅ la forme moderne fonctionne à partir de Python 3.10, donc sur tous les runtimes Fabric actuels.

## 📝 Cellule 29 : Classe et méthodes magiques : `__init__`, `__repr__`, `__str__`, `__eq__`, `__lt__`

### 🔍 Avant d'exécuter

- **Classe** : un **plan** pour fabriquer des objets qui regroupent des données (`site_id`, `capacite_mw`) et du comportement. `self` désigne l'objet en cours ; `__init__` s'exécute à la création.
- **Méthode magique** : méthode dont le nom est entouré de `__`. **Python l'appelle tout seul** quand on utilise une syntaxe ordinaire.
- **Cinq méthodes** à retenir : `__init__` (création), `__repr__` (texte de **diagnostic**, affiché par le notebook), `__str__` (texte **lisible**, utilisé par `print`), `__eq__` (opérateur `==`) et `__lt__` (opérateur `<`, utilisé par `sorted`).
- **Sans elles** : `print(site)` afficherait une adresse mémoire comme `<__main__.Site object at 0x...>`.

### 💻 Code

```python
# === CELLULE 29 : Classe et méthodes magiques ===
class Site:
    def __init__(self, site_id, capacite_mw):     # appelée par Site("SITE_IND_001", 5.0)
        self.site_id = site_id                    # « self. » : les données sont rangées dans l'objet
        self.capacite_mw = capacite_mw

    def __repr__(self):                           # texte de diagnostic : ce que le notebook affiche
        return f"Site({self.site_id!r}, {self.capacite_mw})"

    def __str__(self):                            # texte lisible : ce que print() affiche
        return f"{self.site_id} ({self.capacite_mw} MW)"

    def __eq__(self, autre):                      # appelée par « a == b » : deux sites sont égaux si même identifiant
        return isinstance(autre, Site) and self.site_id == autre.site_id

    def __lt__(self, autre):                      # appelée par « a < b » (et par sorted) : on compare les capacités
        return self.capacite_mw < autre.capacite_mw

gros = Site("SITE_IND_001", 5.0)
petit = Site("SITE_RES_002", 0.6)

print(gros)                                       # __str__  : SITE_IND_001 (5.0 MW)
print(repr(gros))                                 # __repr__ : Site('SITE_IND_001', 5.0)
print([gros, petit])                              # une liste affiche les __repr__ de ses éléments
print(gros == Site("SITE_IND_001", 999))          # __eq__ : True (même identifiant, capacité différente)
print(petit < gros)                               # __lt__ : True (0.6 < 5.0)
print(sorted([gros, petit]))                      # sorted utilise __lt__ : du plus petit au plus grand
```

### 📤 Résultat

```
SITE_IND_001 (5.0 MW)
Site('SITE_IND_001', 5.0)
[Site('SITE_IND_001', 5.0), Site('SITE_RES_002', 0.6)]
True
True
[Site('SITE_RES_002', 0.6), Site('SITE_IND_001', 5.0)]
```

### 💡 Interprétation

- **`print(gros)`** : lisible (`__str__`) ; **`repr(gros)`** : reconstructible (`__repr__`).
- **Dans une liste** : Python affiche les `__repr__`, d'où `Site('SITE_RES_002', 0.6)`.
- **`==`** : vrai si les identifiants sont égaux, même avec une capacité différente : c'est **vous** qui définissez ce qu'« égal » veut dire.
- **`sorted`** : trie les objets grâce à `__lt__`, sans `key=`.
- **Lien avec pandas** : un `DataFrame` ou une `Series` affichés dans le notebook sont le résultat d'un `__repr__`.

## 📝 Cellule 30 : `lambda`, tri, `filter`

### 🔍 Avant d'exécuter

- **`lambda`** : une fonction anonyme d'**une seule expression** : `lambda s: s["cap"]` = « donne-moi `s["cap"]` pour `s` ».
- **`sorted(liste, key=fonction)`** : trie selon le **critère** renvoyé par la fonction.
- **Hier** : `filter(lambda ...)` pour filtrer ; **aujourd'hui** : une compréhension, plus lisible.

### 💻 Code

```python
# === CELLULE 30 : lambda et tri ===
flotte = [{"id": "SITE_IND_001", "cap": 5.0}, {"id": "SITE_COM_002", "cap": 1.5},
          {"id": "SITE_RES_002", "cap": 0.6}, {"id": "SITE_IND_002", "cap": 3.5}]

# key=lambda s: s["cap"] : « pour trier, regarde la clé "cap" de chaque élément »
tri = sorted(flotte, key=lambda s: s["cap"], reverse=True)     # reverse=True : du plus grand au plus petit
print([s["id"] for s in tri])

# Hier : filter garde les éléments pour lesquels la lambda est vraie
grands = list(filter(lambda s: s["cap"] >= 2, flotte))
# Aujourd'hui : la même chose avec une compréhension
grands = [s for s in flotte if s["cap"] >= 2]
print(len(grands))                                              # 2
```

### 📤 Résultat

```
['SITE_IND_001', 'SITE_IND_002', 'SITE_COM_002', 'SITE_RES_002']
2
```

### 💡 Interprétation

- **Ordre** : `SITE_IND_001`, `SITE_IND_002`, `SITE_COM_002`, `SITE_RES_002` (par capacité décroissante).
- **`key=lambda ...`** : l'usage le plus fréquent d'une `lambda`.
- **`filter`** : encore vu dans du code ancien ; préférer la compréhension.
- **Limite** : au-delà d'une expression simple, écrire une vraie fonction nommée.

## 📝 Cellule 31 : `partial` et `lru_cache`

### 🔍 Avant d'exécuter

- **`partial(fonction, argument=valeur)`** : crée une **nouvelle fonction** dont certains arguments sont déjà remplis.
- **`lru_cache`** : mémorise les résultats ; un même appel n'est calculé **qu'une fois**.
- **`@lru_cache`** : un **décorateur**, c'est-à-dire une ligne posée au-dessus de `def` pour ajouter un comportement à la fonction.
- **Condition** : fonction **pure** (même entrée, même sortie), arguments hachables.

### 💻 Code

```python
# === CELLULE 31 : partial et lru_cache ===
from functools import lru_cache, partial

# partial : « round » avec ndigits=2 déjà rempli ; arrondir_2(x) équivaut à round(x, ndigits=2)
arrondir_2 = partial(round, ndigits=2)
print(arrondir_2(2.34567))                     # 2.35

@lru_cache(maxsize=None)                       # décorateur : mémorise les résultats
def facteur_emission(source):
    print(f"  calcul pour {source}")           # ce message prouve qu'un vrai calcul a lieu
    return {"solaire": 0.032, "eolien": 0.012, "gaz": 0.490}[source]

print(facteur_emission("gaz"), facteur_emission("gaz"))   # deux appels, un seul calcul
print(facteur_emission.cache_info().hits)                 # 1 : nombre de fois où le cache a servi
```

### 📤 Résultat

```
2.35
  calcul pour gaz
0.49 0.49
1
```

### 💡 Interprétation

- **`calcul pour gaz`** n'apparaît qu'**une fois** : le second appel vient du cache.
- **`cache_info().hits`** vaut `1` : une réponse issue du cache.
- **Utile pour** : une conversion ou une consultation coûteuse appelée des milliers de fois avec les mêmes arguments.

## 📝 Cellule 32 : Portée des variables

### 🔍 Avant d'exécuter

- **Portée** : où une variable existe. Une affectation **dans** une fonction crée une variable **locale** ; elle disparaît à la fin de la fonction.
- **`global`** : nécessaire pour **modifier** une variable du niveau supérieur depuis une fonction.
- **Notebook** : les variables des cellules précédentes existent tant que le noyau tourne (`globals()` les liste).

### 💻 Code

```python
# === CELLULE 32 : Portée des variables ===
compteur = 0                                    # variable du niveau supérieur (« globale »)

def incrementer_faux():
    compteur = 1                                # crée une variable LOCALE ; la globale n'est pas touchée
    return compteur

def incrementer():
    global compteur                             # « compteur » désigne ici la variable globale
    compteur += 1
    return compteur

incrementer_faux()
print(compteur)                                 # 0 : inchangé
incrementer()
print(compteur)                                 # 1 : modifié
print("sites" in globals(), "capacite_par_site" in globals())   # les variables des cellules précédentes existent
```

### 📤 Résultat

```
0
1
True True
```

### 💡 Interprétation

- **`0` puis `1`** : `incrementer_faux` n'a rien modifié ; `incrementer` (avec `global`) l'a fait.
- **Dernière ligne** : les variables des cellules précédentes sont **globales** dans le notebook.
- **Conséquence** : une cellule qui dépend d'une variable créée plus haut échoue après un redémarrage du noyau ; d'où la règle **Restart Kernel and Run All** avant de livrer un notebook.

## 📝 Cellule 33 : Fermetures (closures)

### 🔍 Avant d'exécuter

- **Fermeture** : une fonction **définie dans une autre** et qui mémorise les variables de la fonction englobante.
- **Usage** : fabriquer des fonctions **paramétrées** (un seuil, un préfixe).
- **Ici** : `fabrique_detecteur(0.8)` renvoie une fonction qui **se souvient** que le seuil est 0,8.

### 💻 Code

```python
# === CELLULE 33 : Fermetures ===
def fabrique_detecteur(seuil):
    def est_critique(taux):                     # fonction interne
        return taux >= seuil                    # « seuil » vient de la fonction englobante : elle le mémorise
    return est_critique                         # on renvoie la fonction elle-même, sans l'appeler

critique_80 = fabrique_detecteur(0.8)           # une fonction qui se souvient de 0.8
critique_95 = fabrique_detecteur(0.95)          # une autre, qui se souvient de 0.95
print(critique_80(0.85), critique_95(0.85))     # True False : même taux, deux seuils
```

### 📤 Résultat

```
True False
```

### 💡 Interprétation

- **`True False`** : le même taux (0,85) franchit le seuil de 80 %, pas celui de 95 %.
- **Chaque détecteur garde son seuil.**
- **Suite** : ce mécanisme est à la base des **décorateurs** (comme `@lru_cache`).

## 📝 Cellule 34 : Un objet qu'on appelle comme une fonction : `__call__`

### 🔍 Avant d'exécuter

- **Limite d'une fermeture** : le seuil est caché ; on ne peut ni le lire ni le changer.
- **`__call__`** : si une classe la définit, ses objets s'**appellent comme des fonctions** : `detecteur(0.85)` exécute `detecteur.__call__(0.85)`.
- **Bénéfice** : une fonction **avec des données visibles** (`detecteur.seuil`) et un **compteur** d'appels.

### 💻 Code

```python
# === CELLULE 34 : __call__ ===
class Detecteur:
    def __init__(self, seuil):
        self.seuil = seuil                       # donnée visible et modifiable
        self.appels = 0                          # compteur d'appels

    def __call__(self, taux):                    # appelée par detecteur(taux)
        self.appels += 1
        return taux >= self.seuil

detecteur = Detecteur(0.8)
print(detecteur(0.85), detecteur(0.5))           # True False : utilisé comme une fonction
print(detecteur.appels, detecteur.seuil)         # 2 0.8 : données lisibles, contrairement à la fermeture
detecteur.seuil = 0.9                            # et modifiables
print(detecteur(0.85))                           # False : le nouveau seuil s'applique
print(callable(detecteur))                       # True : Python le considère comme appelable
```

### 📤 Résultat

```
True False
2 0.8
False
True
```

### 💡 Interprétation

- **`True False`** : l'objet se comporte comme la fonction `critique_80`.
- **`2 0.8`** : on peut lire le nombre d'appels et le seuil, ce que la fermeture cachait.
- **Modifiable** : `detecteur.seuil = 0.9` change le comportement ; la fermeture n'aurait pas permis cela.
- **Rencontrés ensuite** : les modèles de scikit-learn (Atelier 3) sont des objets avec des méthodes ; `pipeline(...)` et les transformations reposent sur le même principe.

## 📝 Cellule 35 : `try` / `except` / `else` / `finally`

### 🔍 Avant d'exécuter

- **Erreur (exception)** : quand Python ne peut pas exécuter une ligne (`float("abc")`), il **lève** une exception et arrête le programme, sauf si on l'a prévue avec `try`.
- **`try`** : le code qui peut échouer.
- **`except ValueError`** : que faire si **cette** erreur précise survient (jamais un `except:` sans type).
- **`else`** : s'exécute seulement si **aucune** erreur n'a eu lieu.
- **`finally`** : s'exécute **toujours** (nettoyage, trace).

### 💻 Code

```python
# === CELLULE 35 : Gestion des erreurs ===
def convertir_mesure(texte):
    texte = texte.strip()                        # enlève les espaces autour
    return None if texte == "" else float(texte) # texte vide -> None ; sinon conversion (peut lever ValueError)

def lire_valeur(texte):
    try:
        valeur = convertir_mesure(texte)         # ligne qui peut échouer
    except ValueError:                           # seulement l'erreur attendue : texte non numérique
        print(f"  {texte!r} : illisible")
        return None
    else:                                        # aucune erreur : on renvoie la valeur
        return valeur
    finally:                                     # s'exécute dans TOUS les cas, même après un return
        print(f"  {texte!r} traité")

for brut in ("0.865", "abc", ""):                # une valeur correcte, un texte illisible, une valeur vide
    print(lire_valeur(brut))
```

### 📤 Résultat

```
  '0.865' traité
0.865
  'abc' : illisible
  'abc' traité
None
  '' traité
None
```

### 💡 Interprétation

- **`"0.865"`** : convertie en `0.865`.
- **`"abc"`** : `ValueError` capturée, la fonction renvoie `None`.
- **`""`** : renvoie `None` (valeur manquante, pas une erreur).
- **`finally`** : la ligne « traité » apparaît **à chaque fois**, avant le résultat.
- **Règle** : intercepter **uniquement l'erreur attendue** ; un `except Exception` trop large masque de vrais bugs.
- **Suite** : `convertir_mesure` sera déplacée dans un module (Partie 6).

## 📝 Cellule 36 : Erreurs métier et chaînage `raise ... from`

### 🔍 Avant d'exécuter

- **Classe d'erreur dédiée** : `class TimestampInvalide(ValueError)` crée un **nouveau type d'erreur** qui hérite de `ValueError`.
- **`raise`** : lève une exception soi-même.
- **`raise ... from erreur`** : garde la **cause d'origine** (`__cause__`).
- **Bénéfice** : un message clair pour l'utilisateur, la trace technique conservée pour le diagnostic.

### 💻 Code

```python
# === CELLULE 36 : raise ... from ===
from datetime import datetime

class TimestampInvalide(ValueError):             # notre erreur métier : hérite de ValueError, corps vide
    """Levée quand un timestamp ne correspond à aucun format connu."""

def horodatage(texte):
    try:
        # strptime : texte -> datetime, selon le format (%Y année, %m mois, %d jour, %H heure, %M minute, %S seconde)
        return datetime.strptime(texte, "%Y-%m-%dT%H:%M:%S")
    except ValueError as erreur:                 # « as erreur » : on récupère l'erreur d'origine
        # On lève notre erreur métier ; « from erreur » garde la cause d'origine
        raise TimestampInvalide(f"Format inconnu : {texte!r}") from erreur

try:
    horodatage("hier soir")                      # ce texte n'est pas une date
except TimestampInvalide as erreur:              # l'appelant n'a besoin de connaître que notre erreur
    print(f"{erreur} <- cause : {erreur.__cause__}")
```

### 📤 Résultat

```
Format inconnu : 'hier soir' <- cause : time data 'hier soir' does not match format '%Y-%m-%dT%H:%M:%S'
```

### 💡 Interprétation

- **`Format inconnu : 'hier soir'`** : le message métier, clair.
- **`cause : ...`** : l'erreur technique de `strptime`, conservée.
- **Bénéfice** : l'appelant intercepte `TimestampInvalide` sans connaître `strptime`.

## 📝 Cellule 37 : Groupes d'exceptions : `except*` et `add_note` (3.11)

### 🔍 Avant d'exécuter

- **Besoin** : valider un lot de 1 000 lignes et **toutes** les erreurs d'un coup, plutôt que s'arrêter à la première.
- **`ExceptionGroup`** (3.11+) : regroupe **plusieurs** erreurs dans une seule.
- **`except*`** : intercepte une famille d'erreurs dans le groupe.
- **`add_note`** : ajoute du contexte (par exemple le numéro de ligne) à une exception.

### 💻 Code

```python
# === CELLULE 37 : ExceptionGroup, except*, add_note ===
def valider_lot(valeurs):
    erreurs = []                                      # on collecte les erreurs au lieu de s'arrêter
    for i, v in enumerate(valeurs):
        try:
            float(v)
        except ValueError as e:
            e.add_note(f"ligne {i}")                  # on attache le numéro de ligne à l'erreur
            erreurs.append(e)
    if erreurs:
        raise ExceptionGroup("Lot invalide", erreurs) # un seul « raise » pour toutes les erreurs

try:
    valider_lot(["0.5", "x", "1.2", "y"])             # deux valeurs invalides : "x" (ligne 1) et "y" (ligne 3)
except* ValueError as groupe:                         # « except* » : le groupe contient toutes les ValueError
    print(len(groupe.exceptions), "erreurs :", [e.__notes__[0] for e in groupe.exceptions])
```

### 📤 Résultat

```
2 erreurs : ['ligne 1', 'ligne 3']
```

### 💡 Interprétation

- **`2 erreurs : ['ligne 1', 'ligne 3']`** : toutes les erreurs du lot sont rapportées ensemble.
- **Comparaison** : un `try` classique s'arrêterait à la première.
- **Compatibilité** : ✅ Python 3.11+ (Runtime 1.3 inclus) ; à éviter si le code doit tourner sous 3.10.

## 📝 Cellule 38 : Dates : lecture de plusieurs formats

### 🔍 Avant d'exécuter

- **`strptime(texte, format)`** : texte → `datetime`.
- **`strftime(format)`** : `datetime` → texte.
- **`timedelta`** : une durée ; s'ajoute à un `datetime`.
- **Codes de format** : `%Y` année, `%m` mois, `%d` jour, `%H` heure, `%M` minute, `%S` seconde.
- **Le fichier de l'atelier** mélange **trois formats** : la fonction essaie chacun jusqu'au succès.

### 💻 Code

```python
# === CELLULE 38 : Dates — formats multiples ===
from datetime import datetime, timedelta

# Les trois formats présents dans le fichier de mesures
FORMATS_TIMESTAMP = ("%Y-%m-%dT%H:%M:%S", "%Y-%m-%d %H:%M:%S", "%d/%m/%Y %H:%M:%S")

def parse_timestamp(texte):
    for fmt in FORMATS_TIMESTAMP:                       # on essaie chaque format à tour de rôle
        try:
            return datetime.strptime(texte.strip(), fmt) # succès : on renvoie tout de suite
        except ValueError:
            continue                                     # échec : format suivant
    raise TimestampInvalide(f"Format inconnu : {texte!r}")  # aucun format ne convient

bruts = ["2025-01-03T04:30:00", "2025-01-03 04:30:00", "03/01/2025 04:30:00"]   # trois écritures du même instant
parses = [parse_timestamp(t) for t in bruts]
print(parses[0], all(p == parses[0] for p in parses))   # all(...) : vrai si TOUTES les comparaisons sont vraies

debut = parses[0]
print(debut + timedelta(minutes=15))                    # ajout d'une durée de 15 minutes
print(debut.strftime("%d/%m/%Y %Hh%M"))                 # datetime -> texte au format français
print(debut.weekday())                                  # jour de la semaine : lundi = 0
```

### 📤 Résultat

```
2025-01-03 04:30:00 True
2025-01-03 04:45:00
03/01/2025 04h30
4
```

### 💡 Interprétation

- **`True`** : les trois écritures désignent le **même instant**.
- **`04:45:00`** : `timedelta(minutes=15)` a été ajouté.
- **`weekday()` = `4`** : vendredi (lundi = 0).
- **Cas réel** : ce mélange de formats est celui du jeu de données ; la fonction sera réutilisée dans le module.

## 📝 Cellule 42 : Un dictionnaire accessible par attributs : `__getattr__`

### 🔍 Avant d'exécuter

- **Problème** : `ligne["capacity_mw"]` est long à écrire, on préférerait `ligne.capacity_mw`.
- **`__getattr__`** : Python l'appelle **seulement quand un attribut n'existe pas** (`ligne.capacity_mw` appelle `__getattr__("capacity_mw")`). On y répond avec le dictionnaire.
- **`AttributeError`** : à lever pour un attribut inconnu, sinon `hasattr` et l'auto-complétion se comportent mal.
- **Lien avec pandas** : `df.site_id` fonctionne de la même façon que `df["site_id"]`.

### 💻 Code

```python
# === CELLULE 42 : __getattr__ ===
class Enregistrement:
    def __init__(self, donnees):
        self._donnees = donnees                      # le dictionnaire d'origine

    def __getattr__(self, nom):                      # appelée quand « nom » n'est pas un attribut normal
        try:
            return self._donnees[nom]                # on répond avec la clé du dictionnaire
        except KeyError:
            raise AttributeError(f"pas de champ {nom!r}") from None   # attribut inconnu

    def __repr__(self):
        return f"Enregistrement({self._donnees})"

ligne = Enregistrement(sites_ref[0])                 # une ligne du CSV lu à la cellule précédente
print(ligne.site_id, ligne.capacity_mw)              # au lieu de ligne["site_id"], ligne["capacity_mw"]
print(hasattr(ligne, "region"), hasattr(ligne, "inconnu"))   # True False : hasattr s'appuie sur AttributeError
```

### 📤 Résultat

```
SITE_IND_001 5.0
True False
```

### 💡 Interprétation

- **`ligne.site_id`** : lit la clé du dictionnaire, sans crochets.
- **`hasattr`** : `True` pour une colonne existante, `False` sinon.
- **Attention** : `__getattr__` n'est appelée que si l'attribut est **absent** ; les attributs normaux (`_donnees`) passent avant.
- **pandas** : `df.site_id` et `df["site_id"]` sont équivalents.

## 📝 Cellule 43 : Expressions régulières : chercher un motif

### 🔍 Avant d'exécuter

- **Expression régulière (regex)** : un **motif** qui décrit une forme de texte (« trois lettres majuscules, un tiret bas, trois chiffres »). Le module `re` cherche ou remplace ce motif dans un texte.
- **Briques du motif** : `\d` un chiffre, `[A-Z]` une lettre majuscule, `{3}` exactement 3 fois, `+` une fois ou plus, `-?` un tiret facultatif, `( )` un **groupe** à récupérer.
- **Fonctions** : `re.search` (premier résultat), `re.findall` (tous), `re.fullmatch` (le texte **entier** correspond-il ?).
- **Notation `r"..."`** : texte « brut » ; le `\` reste tel quel, ce qui évite de le doubler.

### 💻 Code

```python
# === CELLULE 43 : Expressions régulières — chercher ===
import re

texte = "Alerte 2025-01-03T04:30:00 sur SITE_COM_002 : code -999, puis SITE_IND_001 : code -888"

# Motif d'un identifiant de site : SITE_ + 3 lettres majuscules + _ + 3 chiffres
motif_site = r"SITE_[A-Z]{3}_\d{3}"

m = re.search(motif_site, texte)               # search : le PREMIER résultat, ou None
print(m.group(), "| position", m.start())      # group() : le texte trouvé ; start() : où

print(re.findall(motif_site, texte))           # findall : TOUS les résultats, dans une liste
print(re.findall(r"-\d{3}", texte))            # tous les codes négatifs à 3 chiffres

# Les parenthèses créent des GROUPES : on récupère séparément la famille et le numéro
m = re.search(r"SITE_([A-Z]{3})_(\d{3})", texte)
print(m.groups(), "| famille =", m.group(1))

# fullmatch : le texte ENTIER doit correspondre (validation d'un identifiant)
for candidat in ("SITE_IND_001", "SITE_IND_1", "site_ind_001"):
    print(f"{candidat:<14} valide : {bool(re.fullmatch(motif_site, candidat))}")
```

### 📤 Résultat

```
SITE_COM_002 | position 31
['SITE_COM_002', 'SITE_IND_001']
['-999', '-888']
('COM', '002') | famille = COM
SITE_IND_001   valide : True
SITE_IND_1     valide : False
site_ind_001   valide : False
```

### 💡 Interprétation

- **`SITE_COM_002 | position 31`** : le premier site trouvé et sa position.
- **`findall`** : les deux identifiants `SITE_COM_002`, `SITE_IND_001` ; et les deux codes `-999`, `-888`.
- **Groupes** : `('COM', '002')` ; `group(1)` donne la famille.
- **`fullmatch`** : seul `SITE_IND_001` est valide ; `SITE_IND_1` (un seul chiffre) et `site_ind_001` (minuscules) sont refusés.
- **Usage** : valider des identifiants, extraire des valeurs d'un texte, lire des journaux.

## 📝 Cellule 44 : Expressions régulières : remplacer et classer

### 🔍 Avant d'exécuter

- **`re.sub(motif, remplacement, texte)`** : **remplace** chaque occurrence du motif.
- **Références aux groupes** : `\1`, `\2`, `\3` reprennent ce que les groupes ont trouvé (ici pour **réordonner** une date).
- **Groupes nommés** : `(?P<site>...)` donne un nom au groupe ; `groupdict()` renvoie un dictionnaire.
- **`re.compile(motif)`** : prépare le motif une fois, utile quand on le réutilise sur beaucoup de lignes.

### 💻 Code

```python
# === CELLULE 44 : Expressions régulières — remplacer et classer ===

# --- 1. Remplacer : masquer les codes d'erreur
print(re.sub(r"-\d{3}", "<CODE>", texte))

# --- 2. Réordonner une date : (année)-(mois)-(jour) devient jour/mois/année
#     \1 = année, \2 = mois, \3 = jour
print(re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\3/\2/\1", "2025-01-03"))

# --- 3. Groupes nommés : lire une ligne de journal dans un dictionnaire
LIGNE = re.compile(r"(?P<ts>\S+) (?P<site>SITE_\w+) (?P<niveau>[A-Z]+) (?P<code>-?\d+)")
extrait = LIGNE.search("2025-01-03T04:30:00 SITE_COM_002 ERROR -999")
print(extrait.groupdict())

# --- 4. Classer les formats de date du vrai fichier de mesures
FORMATS_REGEX = {
    "ISO avec T":      re.compile(r"^\d{4}-\d{2}-\d{2}T"),        # 2025-01-03T04:30:00
    "ISO avec espace": re.compile(r"^\d{4}-\d{2}-\d{2} "),        # 2025-01-03 04:30:00
    "Jour/Mois/Année": re.compile(r"^\d{2}/\d{2}/\d{4} "),        # 03/01/2025 04:30:00
}
with open(DATA / "consommation_echantillon.csv", encoding="utf-8-sig", newline="") as f:
    horodatages = [ligne["timestamp"] for ligne in csv.DictReader(f)]

for nom, motif in FORMATS_REGEX.items():
    print(f"{nom:<16} : {sum(1 for h in horodatages if motif.match(h))} lignes")   # match : motif au DÉBUT du texte
```

### 📤 Résultat

```
Alerte 2025-01-03T04:30:00 sur SITE_COM_002 : code <CODE>, puis SITE_IND_001 : code <CODE>
03/01/2025
{'ts': '2025-01-03T04:30:00', 'site': 'SITE_COM_002', 'niveau': 'ERROR', 'code': '-999'}
ISO avec T       : 103 lignes
ISO avec espace  : 21 lignes
Jour/Mois/Année  : 26 lignes
```

### 💡 Interprétation

- **`sub`** : `Alerte ... code <CODE>, puis ... code <CODE>`.
- **Date réordonnée** : `2025-01-03` → `03/01/2025`, grâce à `\3/\2/\1`.
- **`groupdict()`** : `{'ts': ..., 'site': 'SITE_COM_002', 'niveau': 'ERROR', 'code': '-999'}` : une ligne de texte devient un enregistrement.
- **Classement** : les trois formats du fichier, avec leur nombre de lignes ; la somme fait **150**.
- **`match` / `search`** : `match` ne cherche qu'**au début** du texte ; `search` cherche partout.
- **Fabric** : PySpark propose les mêmes outils sur des colonnes : `regexp_extract`, `regexp_replace`.

## 📝 Cellule 45 : Fichiers : écrire du JSON, lire du TOML

### 🔍 Avant d'exécuter

## 📝 Cellule 46 : Gestionnaire de contexte : `with`, `__enter__`, `__exit__`

### 🔍 Avant d'exécuter

- **`with`** : garantit qu'un **nettoyage** a lieu, même en cas d'erreur (`with open(...)` ferme le fichier tout seul).
- **Comment ça marche** : `with objet as x:` appelle `objet.__enter__()` au début (son résultat va dans `x`), puis `objet.__exit__(...)` à la fin, **même si une erreur est survenue**.
- **Exemple** : un chronomètre qui mesure la durée d'un bloc. `__exit__` reçoit l'erreur éventuelle et renvoie `False` pour **ne pas la masquer**.

### 💻 Code

```python
# === CELLULE 46 : Gestionnaire de contexte ===
import time

class Chronometre:
    def __enter__(self):                         # appelée à l'entrée du « with »
        self.debut = time.perf_counter()
        self.erreur = None
        return self                              # devient la variable après « as »

    def __exit__(self, type_erreur, erreur, trace):   # appelée à la sortie, même après une erreur
        self.duree = time.perf_counter() - self.debut
        self.erreur = erreur                     # None si tout s'est bien passé
        return False                             # False : l'erreur éventuelle continue de remonter

# Cas normal : on mesure la lecture du fichier
with Chronometre() as chrono:
    lignes_mesures = list(csv.DictReader(open(DATA / "consommation_echantillon.csv", encoding="utf-8-sig", newline="")))
print(len(lignes_mesures), "lignes | durée mesurée :", chrono.duree >= 0)

# Cas d'erreur : __exit__ est appelée quand même
try:
    with Chronometre() as chrono2:
        float("abc")                             # lève une ValueError
except ValueError:
    print("erreur vue par __exit__ :", type(chrono2.erreur).__name__, "| durée mesurée :", chrono2.duree >= 0)
```

### 📤 Résultat

```
150 lignes | durée mesurée : True
erreur vue par __exit__ : ValueError | durée mesurée : True
```

### 💡 Interprétation

- **`150 lignes`** : le fichier lu ; `chrono.duree` a été rempli par `__exit__`.
- **Cas d'erreur** : `__exit__` a bien été appelée et a vu la `ValueError`, avant que celle-ci ne remonte.
- **Même mécanique que `with open(...)`** : le fichier est fermé automatiquement à la sortie.
- **Usage réel** : connexions, verrous, transactions, chronométrage d'une transformation.

```python
"""energie_utils.py — Utilitaires de qualité de données du réseau EnergiaNord."""
import csv
from datetime import datetime
from types import MappingProxyType
from typing import Iterator

CODES_ERREUR = MappingProxyType({
    -999: "Capteur hors service",
    -888: "Valeur non transmise",
    -777: "Recalibrage en cours",
})

FORMATS_TIMESTAMP = (
    "%Y-%m-%dT%H:%M:%S",
    "%Y-%m-%d %H:%M:%S",
    "%d/%m/%Y %H:%M:%S",
)


class TimestampInvalide(ValueError):
    """Levée quand un timestamp ne correspond à aucun format connu."""


def parse_timestamp(texte: str) -> datetime:
    """Convertit un timestamp texte (3 formats possibles) en datetime."""
    for fmt in FORMATS_TIMESTAMP:
        try:
            return datetime.strptime(texte.strip(), fmt)
        except ValueError:
            continue
    raise TimestampInvalide(f"Format inconnu : {texte!r}")


def convertir_mesure(texte: str) -> float | None:
    """'' -> None ; '0.865' -> 0.865 ; '-999' -> -999.0"""
    texte = texte.strip()
    if texte == "":
        return None
    return float(texte)
```

## 📝 Cellule 50 : Où Python cherche-t-il un module ?

### 🔍 Avant d'exécuter

- **Règle** : quand on écrit `import x`, Python cherche `x` **dans cet ordre**, et s'arrête au premier trouvé :
  1. les modules **intégrés** à Python (`sys`, `time`…) ;
  2. le **dossier du script ou du notebook** en cours (première entrée de `sys.path`) ;
  3. les dossiers listés dans la variable d'environnement **`PYTHONPATH`** (si elle existe) ;
  4. la **bibliothèque standard** (`json`, `csv`, `pathlib`…) ;
  5. le dossier **`site-packages` de l'environnement virtuel** (ce que `pip install` a installé).
- **Sinon** : `ModuleNotFoundError`.
- **Conséquence** : `energie_utils.py` doit se trouver **dans le dossier du notebook** (ou dans un dossier de `sys.path`).
- **`sys.path`** : la liste réelle de ces dossiers, dans l'ordre.

### 💻 Code

```python
# === CELLULE 50 : sys.path et modules trouvés ===
import sys
import importlib.util

# La liste ordonnée des dossiers où Python cherche
for rang, dossier in enumerate(sys.path):
    print(rang, dossier)

print()
# Où se trouve energie_utils ? Dans le dossier de travail : le premier de la liste
origine = Path(importlib.util.find_spec("energie_utils").origin)
print("energie_utils.py est dans le dossier courant :", origine.parent == Path.cwd())

# json est dans la bibliothèque standard ; un module qui n'existe nulle part donne None
print(importlib.util.find_spec("json") is not None, importlib.util.find_spec("module_inexistant"))

try:
    import module_inexistant              # introuvable dans tous les dossiers
except ModuleNotFoundError as erreur:
    print(f"ModuleNotFoundError : {erreur}")
```

```python
def qualifier_mesure(valeur: float | None) -> str:
    """Classe une mesure : MANQUANTE, CODE_ERREUR, NEGATIVE ou VALIDE."""
    match valeur:
        case None:
            return "MANQUANTE"
        case v if v in CODES_ERREUR:
            return "CODE_ERREUR"
        case v if v < 0:
            return "NEGATIVE"
        case _:
            return "VALIDE"


def lire_csv(chemin) -> Iterator[dict]:
    """Lit un CSV (UTF-8 avec ou sans BOM) et produit un dictionnaire par ligne."""
    with open(chemin, encoding="utf-8-sig", newline="") as f:
        yield from csv.DictReader(f)
```

## 📝 Cellule 51 : Le module est en cache : `reload`

```python
"""analyse_sites.py — Contrôle qualité des mesures de consommation (Atelier 1).

Usage :
    python analyse_sites.py --input data/consommation_echantillon.csv
    python analyse_sites.py -i data/consommation_echantillon.csv --seuil 0.05 --json
"""
import argparse
import json
import logging
import sys
from collections import Counter, defaultdict
from pathlib import Path

from energie_utils import (TimestampInvalide, convertir_mesure, lire_csv,
                           parse_timestamp, qualifier_mesure)

log = logging.getLogger("analyse_sites")


def compter(chemin_mesures: Path) -> dict:
    """Parcourt le fichier : états par site, somme des valeurs valides, doublons."""
    vues = set()
    qualite = defaultdict(Counter)
    somme_mw = defaultdict(float)
    doublons = horodatages_invalides = 0

    for ligne in lire_csv(chemin_mesures):
        cle = tuple(ligne.values())
        if cle in vues:                       # doublon exact : on l'écarte
            doublons += 1
            continue
        vues.add(cle)

        try:
            parse_timestamp(ligne["timestamp"])
        except TimestampInvalide:
            horodatages_invalides += 1

        etat = qualifier_mesure(convertir_mesure(ligne["consumption_mw"]))
        qualite[ligne["site_id"]][etat] += 1
        if etat == "VALIDE":
            somme_mw[ligne["site_id"]] += float(ligne["consumption_mw"])

    return {"qualite": qualite, "somme_mw": somme_mw, "doublons": doublons,
            "horodatages_invalides": horodatages_invalides}
```

```python
def analyser(chemin_mesures: Path, chemin_sites: Path) -> dict:
    """Calcule les indicateurs qualité et charge par site."""
    sites = {s["site_id"]: s for s in lire_csv(chemin_sites)}
    brut = compter(chemin_mesures)

    par_site = {}
    for site_id, compteur in sorted(brut["qualite"].items()):
        total = sum(compteur.values())
        valides = compteur["VALIDE"]
        conso_moyenne = brut["somme_mw"][site_id] / valides if valides else 0.0
        capacite = float(sites[site_id]["capacity_mw"])
        par_site[site_id] = {
            "mesures": total,
            "valides": valides,
            "manquantes": compteur["MANQUANTE"],
            "codes_erreur": compteur["CODE_ERREUR"],
            "taux_anomalies": round((total - valides) / total, 3),
            "conso_moyenne_mw": round(conso_moyenne, 3),
            "taux_charge_moyen": round(conso_moyenne / capacite, 3),
        }

    total = sum(s["mesures"] for s in par_site.values())
    anomalies = sum(s["mesures"] - s["valides"] for s in par_site.values())
    return {
        "sites": par_site,
        "doublons_ecartes": brut["doublons"],
        "horodatages_invalides": brut["horodatages_invalides"],
        "taux_anomalies_global": round(anomalies / total, 3),
    }
```

```python
def afficher(rapport: dict) -> None:
    print(f"{'Site':<14}{'Mesures':>8}{'Valides':>9}{'Manq.':>7}{'Codes':>7}{'Anom.':>8}{'Charge':>9}")
    for site_id, s in rapport["sites"].items():
        print(f"{site_id:<14}{s['mesures']:>8}{s['valides']:>9}{s['manquantes']:>7}"
              f"{s['codes_erreur']:>7}{s['taux_anomalies']:>8.1%}{s['taux_charge_moyen']:>9.1%}")
    print(f"Doublons écartés      : {rapport['doublons_ecartes']}")
    print(f"Horodatages invalides : {rapport['horodatages_invalides']}")
    print(f"Taux d'anomalies      : {rapport['taux_anomalies_global']:.1%}")


def lire_arguments(argv=None) -> argparse.Namespace:
    parser = argparse.ArgumentParser(prog="analyse_sites", description=__doc__.splitlines()[0])
    parser.add_argument("--input", "-i", required=True, type=Path, help="fichier CSV des mesures")
    parser.add_argument("--sites", type=Path, default=Path("data/sites_reference.csv"),
                        help="référentiel des sites (défaut : %(default)s)")
    parser.add_argument("--seuil", type=float, default=0.10, help="taux d'anomalies maximal toléré")
    parser.add_argument("--json", action="store_true", help="écrire out/rapport_qualite.json")
    return parser.parse_args(argv)


def main(argv=None) -> int:
    logging.basicConfig(level=logging.INFO, format="%(levelname)s | %(message)s")
    args = lire_arguments(argv)

    log.info("Analyse de %s", args.input)
    rapport = analyser(args.input, args.sites)
    afficher(rapport)

    if args.json:
        Path("out").mkdir(exist_ok=True)
        Path("out/rapport_qualite.json").write_text(
            json.dumps(rapport, indent=2, ensure_ascii=False), encoding="utf-8")
        log.info("Rapport écrit dans out/rapport_qualite.json")

    if rapport["taux_anomalies_global"] > args.seuil:
        log.error("Seuil dépassé : %.1f %% > %.1f %%",
                  rapport["taux_anomalies_global"] * 100, args.seuil * 100)
        return 1
    log.info("Qualité conforme au seuil")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```
