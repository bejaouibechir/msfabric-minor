### 4. Petit exemple : pourquoi un environnement virtuel ?

Deux projets ont besoin de **deux versions différentes** de la même bibliothèque. On le simule avec `python-dateutil` (bibliothèque de dates), dans deux environnements jetables `env_a` et `env_b`.

```powershell
# Projet A : version ancienne épinglée
python -m venv env_a
env_a\Scripts\activate.bat
pip install python-dateutil==2.8.2
python -c "import dateutil; print(dateutil.__version__)"
pip freeze
deactivate
```

```text

python-dateutil==2.8.2
six==1.17.0
```

```powershell
# Projet B : dernière version
python -m venv env_b
env_b\Scripts\activate.bat
pip install python-dateutil
python -c "import dateutil; print(dateutil.__version__)"
pip freeze
deactivate
```

```text
2.9.0.post0
python-dateutil==2.9.0.post0
six==1.17.0
```

```powershell

```

```text

```

Les numéros de version affichés dépendent du jour d'installation.

- **Isolation** : chaque projet a sa propre version de la bibliothèque, sans conflit.
- **Propreté** : rien n'a été installé dans le Python du système ni dans `.venv`.
- **Reproductibilité** : `pip freeze` liste ce qu'il faut pour recréer l'environnement (`requirements.txt`).
- **Jetable** : supprimer le dossier `env_a` supprime tout, sans laisser de trace.

> 💡 **Le même principe dans Fabric** : deux notebooks peuvent avoir deux **Environments** avec des bibliothèques différentes, sans se perturber. Sans cette isolation, une mise à jour de bibliothèque pour un projet casserait tous les autres.

## 📝 Cellule 3 : Variables et typage dynamique

### 🔍 Avant d'exécuter

- **Variable** : une étiquette posée sur une valeur ; c'est la **valeur** qui porte le type.
- **`None`** : absence de valeur, l'équivalent de `NULL` en SQL.
- **snake_case** : convention de nommage (`capacity_mw`).

### 💻 Code

```python
# === CELLULE 3 : Variables et typage dynamique ===
site_id = "SITE_IND_001"
capacity_mw = 5.0
flexible = True
nb_mesures = 720
curtailment_price = None

for nom, valeur in [("site_id", site_id), ("capacity_mw", capacity_mw),
                    ("flexible", flexible), ("nb_mesures", nb_mesures),
                    ("curtailment_price", curtailment_price)]:
    print(f"{nom:<18} {valeur!r:<16} {type(valeur).__name__}")

x = 10
x = "dix"                     # même variable, autre type : autorisé
print(type(x).__name__, isinstance(flexible, int))
```

### 📤 Résultat

```
site_id            'SITE_IND_001'   str
capacity_mw        5.0              float
flexible           True             bool
nb_mesures         720              int
curtailment_price  None             NoneType
str True
```

### 💡 Interprétation

Le typage est **dynamique** (type connu à l'exécution) mais **fort** : `"dix" + 1` est refusé. `isinstance(flexible, int)` vaut `True` car `bool` est une sous-classe de `int` (`True == 1`), détail qui réapparaît en pandas quand une colonne de booléens est utilisée dans des calculs.

## 📝 Cellule 4 : Nombres : division, flottants, `Decimal`

### 🔍 Avant d'exécuter

- **`/` et `//`** : `/` renvoie toujours un flottant ; `//` est la division entière.
- **`float`** : stocké en binaire, donc `0.1 + 0.2 != 0.3` ; comparer avec `math.isclose`.
- **`Decimal`** : exact, pour les montants.

```python
# ❌ Python 2 — comportement supprimé
print 7 / 2            # affichait 3 : division ENTIÈRE entre deux entiers
```

### 💻 Code

```python
# === CELLULE 4 : Nombres — division, flottants, Decimal ===
import math
from decimal import Decimal

print(7 / 2, 7 // 2, 7 % 2, 2 ** 10)
print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
print(math.isclose(0.1 + 0.2, 0.3))
print(Decimal("0.1") + Decimal("0.2"))
```

### 📤 Résultat

```
3.5 3 1 1024
0.30000000000000004 False
True
0.3
```

### 💡 Interprétation

`7 / 2` vaut `3.5` et `7 // 2` vaut `3` : l'ambiguïté de Python 2 a disparu. L'écart `0.30000000000000004` est inhérent aux flottants binaires et se retrouve à l'identique en pandas et en Spark : on compare avec une tolérance, jamais avec `==`.

## 📝 Cellule 5 : Nombres : arrondi, grands entiers, `NaN` et `None`

### 🔍 Avant d'exécuter

- **`round`** : arrondi « au pair le plus proche » (`round(2.5)` donne `2`).
- **`int`** : sans limite de taille ; `_` sépare les milliers.
- **`NaN`** : un flottant particulier, jamais égal à lui-même ; distinct de `None`.

### 💻 Code

```python
# === CELLULE 5 : Arrondi, grands entiers, NaN et None ===
print(round(0.5), round(1.5), round(2.5), round(3.5))
print(round(2.675, 2))
print(1_000_000 * 1.5, 2 ** 100)

valeur_nan = float("nan")
print(valeur_nan == valeur_nan, math.isnan(valeur_nan))
print(None == 0, None is None)
```

### 📤 Résultat

```
0 2 2 4
2.67
1500000.0 1267650600228229401496703205376
False True
False True
```

### 💡 Interprétation

`0 2 2 4` surprend beaucoup de participants. **Point d'attention** : `round` de Python et de pandas (NumPy) arrondit au pair, alors que `round` de Spark SQL arrondit « demi vers le haut » (`HALF_UP`) ; Spark propose `bround` pour l'arrondi au pair. `round(2.675, 2)` donne `2.67` et non `2.68` (`2.675` n'est pas représentable exactement en binaire). Un même calcul peut donc différer entre un notebook pandas et un notebook PySpark. Pour détecter un `NaN`, on utilise `math.isnan` (ou `isna()` en pandas), jamais `==`.

## 📝 Cellule 6 : Constantes

### 🔍 Avant d'exécuter

- **Convention** : Python n'a pas de vraie constante ; on écrit le nom en MAJUSCULES.
- **`Final`** : indique aux outils d'analyse qu'une réaffectation est une erreur (sans l'empêcher).
- **Immuable** : un **tuple** au lieu d'une liste ; `MappingProxyType` pour un dictionnaire en lecture seule.

### 💻 Code

```python
# === CELLULE 6 : Constantes, Final et MappingProxyType ===
from types import MappingProxyType
from typing import Final

CAPACITE_MAX_MW: Final = 5.0
```

## 📝 Cellule 13 : `match` / `case` : hier et aujourd'hui

### 🔍 Avant d'exécuter

- **Hier** : chaîne de `if` / `elif` pour interpréter un code.
- **Aujourd'hui (3.10+)** : `match` / `case`, un filtrage par **motifs**.
- **`case _`** : cas par défaut ; **`|`** combine plusieurs motifs ; **`if`** ajoute une garde.

### 💻 Code

```python
# === CELLULE 13 : match / case ===
def decrire_ancien(code):                                     # Hier
    if code is None or code == "":
        return "valeur manquante"
    elif code == -999:
        return "capteur hors service"
    elif code == -888 or code == -777:
        return "valeur non transmise ou recalibrage"
    elif isinstance(code, (int, float)) and code >= 0:
        return "mesure valide"
    else:
        return "valeur inattendue"

def decrire(code):                                            # Aujourd'hui (3.10+)
    match code:
        case None | "":
            return "valeur manquante"
        case -999:
            return "capteur hors service"
        case -888 | -777:
            return "valeur non transmise ou recalibrage"
        case int() | float() if code >= 0:
            return "mesure valide"
        case _:
            return "valeur inattendue"

for valeur in (0.865, -999, -888, None, "", "abc"):
    print(f"{valeur!r:>8} -> {decrire(valeur):<38} identique : {decrire(valeur) == decrire_ancien(valeur)}")
```

### 📤 Résultat

```
   0.865 -> mesure valide                          identique : True
    -999 -> capteur hors service                   identique : True
    -888 -> valeur non transmise ou recalibrage    identique : True
    None -> valeur manquante                       identique : True
      '' -> valeur manquante                       identique : True
   'abc' -> valeur inattendue                      identique : True
```

### 💡 Interprétation

Les deux versions donnent les mêmes résultats ; la seconde se lit comme une table de décision. ✅ Disponible dès Python 3.10, donc sur tous les runtimes Fabric actuels.

## 📝 Cellule 16 : `zip` paresseux et `strict=True`

### 🔍 Avant d'exécuter

## 📝 Cellule 21 : Paramètres nommés et valeurs par défaut

## 📝 Cellule 31 : `try` / `except` / `else` / `finally`

### 🔍 Avant d'exécuter

- **`except`** : intercepte un type d'erreur précis (jamais un `except:` nu).
- **`else`** : s'exécute seulement si **aucune** erreur n'a eu lieu.
- **`finally`** : s'exécute **toujours** (fermeture, nettoyage, trace).

### 💻 Code

```python
# === CELLULE 31 : Gestion des erreurs ===
def convertir_mesure(texte):
    texte = texte.strip()
    return None if texte == "" else float(texte)

def lire_valeur(texte):
    try:
        valeur = convertir_mesure(texte)
    except ValueError:
        print(f"  {texte!r} : illisible")
        return None
    else:
        return valeur
    finally:
        print(f"  {texte!r} traité")

for brut in ("0.865", "abc", ""):
    print(lire_valeur(brut))
```

### 📤 Résultat

```
  '0.865' traité
0.865
  'abc' : illisible
  'abc' traité
None
  '' traité
None
```

### 💡 Interprétation

Les trois cas : une valeur correcte, un texte illisible (`ValueError` capturée) et une chaîne vide (`None`, valeur manquante). `finally` s'affiche à chaque fois. **Intercepter uniquement l'erreur attendue** : un `except Exception` trop large masque de vrais bugs. Cette fonction `convertir_mesure` sera déplacée dans un module à la Partie 7.

## 📝 Cellule 32 : Erreurs métier et chaînage `raise ... from`

### 🔍 Avant d'exécuter

- **Classe d'erreur dédiée** : hérite de `ValueError` ou `Exception`.
- **`raise ... from erreur`** : conserve la **cause** d'origine.
- **Bénéfice** : un message clair pour l'utilisateur, la trace technique pour le diagnostic.

### 💻 Code

```python
# === CELLULE 32 : raise ... from ===
from datetime import datetime

class TimestampInvalide(ValueError):
    """Levée quand un timestamp ne correspond à aucun format connu."""

def horodatage(texte):
    try:
        return datetime.strptime(texte, "%Y-%m-%dT%H:%M:%S")
    except ValueError as erreur:
        raise TimestampInvalide(f"Format inconnu : {texte!r}") from erreur

try:
    horodatage("hier soir")
except TimestampInvalide as erreur:
    print(f"{erreur} <- cause : {erreur.__cause__}")
```

### 📤 Résultat

```
Format inconnu : 'hier soir' <- cause : time data 'hier soir' does not match format '%Y-%m-%dT%H:%M:%S'
```

### 💡 Interprétation

Un appelant peut intercepter `TimestampInvalide` (erreur métier) sans connaître les détails de `strptime`, tout en gardant la cause d'origine pour le diagnostic.

## 📝 Cellule 33 : Groupes d'exceptions : `except*` et `add_note` (3.11)

### 🔍 Avant d'exécuter

- **`ExceptionGroup`** (3.11+) : regroupe **plusieurs** erreurs dans une seule.
- **`except*`** : intercepte une famille d'erreurs à l'intérieur du groupe.
- **`add_note`** : ajoute du contexte (n° de ligne) à une exception.

### 💻 Code

```python
# === CELLULE 33 : ExceptionGroup, except*, add_note ===
def valider_lot(valeurs):
    erreurs = []
    for i, v in enumerate(valeurs):
        try:
            float(v)
        except ValueError as e:
            e.add_note(f"ligne {i}")
            erreurs.append(e)
    if erreurs:
        raise ExceptionGroup("Lot invalide", erreurs)

try:
    valider_lot(["0.5", "x", "1.2", "y"])
except* ValueError as groupe:
    print(len(groupe.exceptions), "erreurs :", [e.__notes__[0] for e in groupe.exceptions])
```

### 📤 Résultat

```
2 erreurs : ['ligne 1', 'ligne 3']
```

### 💡 Interprétation

Au lieu de s'arrêter à la première ligne invalide, on **collecte** toutes les erreurs d'un lot et on les rapporte ensemble. ✅ Python 3.11+ (Runtime 1.3 inclus) ; à éviter si votre code doit tourner sous 3.10.

## 📝 Cellule 34 : Dates : lecture de plusieurs formats

### 🔍 Avant d'exécuter

- **`strptime`** : texte → `datetime` selon un format (`%Y-%m-%d %H:%M:%S`).
- **`strftime`** : `datetime` → texte.
- **`timedelta`** : durée ; s'ajoute à un `datetime`.

### 💻 Code

```python
# === CELLULE 34 : Dates — formats multiples ===
from datetime import datetime, timedelta

FORMATS_TIMESTAMP = ("%Y-%m-%dT%H:%M:%S", "%Y-%m-%d %H:%M:%S", "%d/%m/%Y %H:%M:%S")

def parse_timestamp(texte):
    for fmt in FORMATS_TIMESTAMP:
        try:
            return datetime.strptime(texte.strip(), fmt)
        except ValueError:
            continue
    raise TimestampInvalide(f"Format inconnu : {texte!r}")

bruts = ["2025-01-03T04:30:00", "2025-01-03 04:30:00", "03/01/2025 04:30:00"]
parses = [parse_timestamp(t) for t in bruts]
print(parses[0], all(p == parses[0] for p in parses))

debut = parses[0]
print(debut + timedelta(minutes=15), debut.strftime("%d/%m/%Y %Hh%M"), debut.weekday())
```

### 📤 Résultat

```
2025-01-03 04:30:00 True
2025-01-03 04:45:00 03/01/2025 04h30 4
```

### 💡 Interprétation

Les trois écritures du fichier source désignent le même instant. Le jeu de données de l'atelier mélange ces formats : la fonction essaie chacun jusqu'au succès. `weekday()` renvoie `4` (vendredi, lundi = 0).

## 📝 Cellule 40 : Préparer les tests de compatibilité

### 🔍 Avant d'exécuter

- **Objectif** : savoir si une fonctionnalité existe dans **le** Python utilisé.
- **Syntaxe nouvelle** : testée avec `compile()`, car une `SyntaxError` ne se rattrape pas à l'exécution.
- **Module nouveau** : testé avec `import` + `hasattr`.

### 💻 Code

```python
# === CELLULE 40 : Outils de test de compatibilité ===
import importlib
import sys

def syntaxe_ok(source):
    try:
        compile(source, "<test>", "exec")
        return True
    except SyntaxError:
        return False

def module_ok(nom, attribut=None):
    try:
        module = importlib.import_module(nom)
    except ImportError:
        return False
    return attribut is None or hasattr(module, attribut)

def zip_strict_ok():
    try:
        list(zip([1], [2, 3], strict=True))
    except ValueError:
        return True
    return False
```

### 📤 Résultat

```python
from datetime import datetime
from types import MappingProxyType
from typing import Iterator

CODES_ERREUR = MappingProxyType({
    -999: "Capteur hors service",
    -888: "Valeur non transmise",

FORMATS_TIMESTAMP = (
    "%Y-%m-%dT%H:%M:%S",
    "%Y-%m-%d %H:%M:%S",
    "%d/%m/%Y %H:%M:%S",
)


class TimestampInvalide(ValueError):
    """Levée quand un timestamp ne correspond à aucun format connu."""


def parse_timestamp(texte: str) -> datetime:
    """Convertit un timestamp texte (3 formats possibles) en datetime."""
    for fmt in FORMATS_TIMESTAMP:
```

```python
def qualifier_mesure(valeur: float | None) -> str:
    """Classe une mesure : MANQUANTE, CODE_ERREUR, NEGATIVE ou VALIDE."""
    match valeur:
        case None:
            return "MANQUANTE"
        case v if v in CODES_ERREUR:
            return "CODE_ERREUR"
        case v if v < 0:
            return "NEGATIVE"
        case _:

    """Lit un CSV (UTF-8 avec ou sans BOM) et produit un dictionnaire par ligne."""
    with open(chemin, encoding="utf-8-sig", newline="") as f:
        yield from csv.DictReader(f)
''')
```

## 📝 Cellule 51 : Assembler le script (1/3) : comptage

### 🔍 Avant d'exécuter

- **Objectif** : un **script** `analyse_sites.py` qui **réutilise** `energie_utils`.
- **Étape 1** : parcourir le fichier, écarter les doublons, compter les états par site.
- **Structures** : `defaultdict(Counter)` et `set` des lignes déjà vues.

### 💻 Code

```python
# === CELLULE 51 : analyse_sites.py — comptage ===
Path("analyse_sites.py").write_text('''"""analyse_sites.py — Contrôle qualité des mesures de consommation (Atelier 1).

Usage :
    python analyse_sites.py --input data/consommation_echantillon.csv
    python analyse_sites.py -i data/consommation_echantillon.csv --seuil 0.05 --json
"""
import argparse
import json
import logging
import sys
from collections import Counter, defaultdict
from pathlib import Path

from energie_utils import (TimestampInvalide, convertir_mesure, lire_csv,
                           parse_timestamp, qualifier_mesure)

log = logging.getLogger("analyse_sites")


def compter(chemin_mesures: Path) -> dict:
    """Parcourt le fichier : états par site, somme des valeurs valides, doublons."""
    vues = set()
    qualite = defaultdict(Counter)
    somme_mw = defaultdict(float)
    doublons = horodatages_invalides = 0

    for ligne in lire_csv(chemin_mesures):
        cle = tuple(ligne.values())
        if cle in vues:                       # doublon exact : on l'écarte
            doublons += 1
            continue
        vues.add(cle)

        try:
            parse_timestamp(ligne["timestamp"])
        except TimestampInvalide:
            horodatages_invalides += 1

        etat = qualifier_mesure(convertir_mesure(ligne["consumption_mw"]))
        qualite[ligne["site_id"]][etat] += 1
        if etat == "VALIDE":
            somme_mw[ligne["site_id"]] += float(ligne["consumption_mw"])

    return {"qualite": qualite, "somme_mw": somme_mw, "doublons": doublons,
            "horodatages_invalides": horodatages_invalides}
''', encoding="utf-8")
print("analyse_sites.py :", len(Path("analyse_sites.py").read_text(encoding="utf-8").splitlines()), "lignes")
```

```python
            "taux_anomalies": round((total - valides) / total, 3),
            "conso_moyenne_mw": round(conso_moyenne, 3),
            "taux_charge_moyen": round(conso_moyenne / capacite, 3),
        }

    total = sum(s["mesures"] for s in par_site.values())
    anomalies = sum(s["mesures"] - s["valides"] for s in par_site.values())
    return {
        "sites": par_site,
        "doublons_ecartes": brut["doublons"],
        "horodatages_invalides": brut["horodatages_invalides"],
        "taux_anomalies_global": round(anomalies / total, 3),
    }
''')
print("analyse_sites.py :", len(Path("analyse_sites.py").read_text(encoding="utf-8").splitlines()), "lignes")
```

```
analyse_sites.py : 76 lignes
```

### 💡 Interprétation

Le rôle de chaque fonction est net : `compter` lit, `analyser` calcule. Séparer ainsi lecture et calcul permet de tester chaque étape isolément.

## 🎯 Synthèse de l'atelier Python

### Objectifs réalisés

Vous avez installé un environnement Python reproductible (`venv`, `requirements.txt`, IPython, Jupyter Notebook), démontré l'intérêt de l'isolation avec deux versions d'une même bibliothèque, parcouru le langage (types, chaînes, conditions, `match`, boucles, compréhensions, fonctions, erreurs, dates, fichiers, `logging`), puis rangé le code dans un **module** réutilisable (`energie_utils.py`) et un **script** en ligne de commande (`analyse_sites.py`). Sur le jeu d'essai, il détecte 13 anomalies sur 144 mesures uniques (9,0 %), après avoir écarté 6 doublons.

### Points clés techniques

**Ancien / nouveau** : pour chaque notion, vous avez vu l'écriture historique et l'écriture actuelle, avec la version qui les sépare. Le code à retenir pour Fabric est celui qui fonctionne sur **Python 3.11** (`match`, `int | None`, `dict | dict`, `StrEnum`, `tomllib`, `except*`, `datetime.UTC`) ; les apports de 3.12 et 3.13 sont à réserver aux notebooks dont vous maîtrisez le runtime.

**État partagé** : dans un notebook, les variables persistent d'une cellule à l'autre. Le réflexe **Restart Kernel and Run All** garantit la reproductibilité.

**Modules** : un fichier `.py` remplace le copier-coller entre notebooks ; `reload` (ou `%autoreload`) permet de le modifier sans redémarrer.

### Correspondance avec Microsoft Fabric

| Ce que vous avez utilisé       | Équivalent dans Fabric                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| `venv` + `requirements.txt`    | **Environment** Fabric (bibliothèques publiques et personnalisées)                             |
| `pip install` dans le venv     | `%pip install` (limité à la session du notebook)                                               |
| Module `energie_utils.py`      | Fichier déposé dans **Resources** du notebook, ou bibliothèque `.py` / `.whl` d'un Environment |
| `argparse` / options du script | **Cellule de paramètres** alimentée par un pipeline                                            |
| `config.toml`                  | **Variable Library**                                                                           |
| `data/` (chemin relatif)       | `/lakehouse/default/Files/` (notebook Python, Lakehouse attaché)                               |
| `sys.version`                  | Identifie le runtime : Python 3.11 (Runtime 1.3), 3.12 (noyau Python), 3.13 (Runtime 2.0)      |

### Points clés métier

**Règles à retenir** : ne jamais tester une mesure avec `if valeur:` (un `0` légitime et un `-999` seraient traités à l'inverse de l'attendu) ; ne jamais comparer avec `NaN` par `==` ; stocker les dates en UTC ; déclarer l'encodage à chaque lecture de fichier (BOM). Les anomalies traitées (codes erreur, valeurs manquantes, doublons, formats de date) sont celles que vous nettoierez en PySpark à l'atelier Silver ; le taux de 9,0 % est du même ordre que les 10,3 % du Module 2.
