# Atelier 1 — Du notebook au script de production avec une Spark Job Definition

## Démarche rapide

1. Charger trois fichiers JSON dans `Files/landing_sjd/`.
2. Tester leur lecture et leur transformation dans un notebook Fabric.
3. Charger `energie_sjd_utils.py` dans les ressources intégrées du notebook.
4. Créer une Spark Job Definition avec `ingestion_energie.py` comme fichier principal.
5. Ajouter `energie_sjd_utils.py` comme fichier de référence.
6. Associer `LH_Energie_Bronze` comme Lakehouse par défaut.
7. Exécuter le job pour les trois datasets.
8. Vérifier les tables Delta et démontrer l'idempotence du `MERGE`.
9. Examiner les journaux d'une réussite et d'un échec contrôlé.
10. Appeler la Spark Job Definition depuis un pipeline séquentiel.

---

## Objectifs

Cet atelier transforme une ingestion exploratoire en programme PySpark paramétré et exécutable comme **Spark Job Definition** dans Microsoft Fabric.

À la fin de l'atelier, vous saurez :

- tester le traitement dans un notebook sans lancer `argparse` ;
- utiliser un module Python placé dans les ressources intégrées du notebook ;
- créer et configurer une Spark Job Definition ;
- lire des fichiers OneLake ou une API REST ;
- écrire dans des tables Delta avec un `MERGE` idempotent ;
- superviser le job et l'appeler depuis un pipeline.

**Durée indicative :** 3 h

**Niveau :** avancé

**Langage :** Python et PySpark

---

## Architecture de l'atelier

Le workspace utilisé est `WS_Energie_Renouvelable` et le Lakehouse est `LH_Energie_Bronze`.

| Élément | Emplacement local |
| --- | --- |
| Données JSON | `data input atelier 1/sortie/` |
| Générateur | `data input atelier 1/generer_donnees_atelier1.py` |
| Script principal | `scripts atelier 1/ingestion_energie.py` |
| Module utilitaire | `scripts atelier 1/energie_sjd_utils.py` |

Les identifiants acceptés par le code sont exactement :

| Dataset | Fichier | Table cible | Clé du MERGE |
| --- | --- | --- | --- |
| `besoins` | `besoins.json` | `besoins_energetiques_sjd` | `Timestamp` + `Zone` |
| `production-solaire` | `production-solaire.json` | `production_solaire_sjd` | `PanneauID` + `Date` |
| `production-eolienne` | `production-eolienne.json` | `production_eolienne_sjd` | `TurbineID` + `Timestamp` |

> ⚠️ Utilisez toujours `production-solaire` et `production-eolienne`. Les valeurs `solaire` et `eolien` ne sont pas acceptées par `argparse`.

Le traitement écrit uniquement dans les tables suffixées `_sjd`.

### Cellule 8 — Valider types, clés et doublons

```python
types_obtenus = dict(df.dtypes)

for colonne, type_attendu in config["columns"]:
    type_obtenu = types_obtenus[colonne]
    assert type_obtenu == type_attendu, (
        f"{colonne} : attendu={type_attendu}, obtenu={type_obtenu}"

cles = list(config["key"])

assert nombre_transforme == 30
```

### Cellule 9 — Tester les trois datasets

```python
resultats = []

for nom_dataset in DATASETS:
    cfg = dataset_config(nom_dataset)
    fichier = f"Files/landing_sjd/{cfg['file']}"

    brut = (
        spark.read
             .schema(schema_brut(nom_dataset))
             .option("multiLine", "true")
             .json(fichier)
    )
    transforme = typer_dataframe(brut, nom_dataset, "files")
    resultats.append((nom_dataset, transforme.count(), cfg["table"]))

for nom_dataset, nombre, table in resultats:
    assert nombre == 30, f"{nom_dataset} : {nombre} lignes au lieu de 30"
    print(f"✅ {nom_dataset:22} → {nombre} lignes → {table}")
```

# Partie 3 — Comprendre les scripts

## Étape 6 — Module utilitaire

`energie_sjd_utils.py` contient :

- le dictionnaire `DATASETS` ;
- les noms de fichiers, tables et clés métier ;
- `schema_brut()` pour construire le `StructType` ;
- `typer_dataframe()` pour convertir les types et ajouter les colonnes techniques.

## Étape 7 — Script principal

`ingestion_energie.py` :

1. lit les arguments avec `argparse` ;
2. choisit la source `files` ou `api` ;
3. crée le DataFrame avec le schéma explicite ;
4. applique les conversions ;
5. refuse les clés nulles ;
6. élimine les doublons du lot ;
7. crée la table Delta ou exécute un `MERGE` ;
8. écrit les informations et erreurs dans les journaux.

Arguments acceptés :

```text
--source files|api
--dataset besoins|production-solaire|production-eolienne
--landing-path Files/landing_sjd
--base-url https://...        # uniquement avec --source api
```

# Partie 4 — Créer la Spark Job Definition

## Étape 8 — Créer l'item

1. Dans `WS_Energie_Renouvelable`, sélectionnez **New item**.
2. Recherchez **Spark Job Definition**.
3. Nommez l'item `TEST_SJD_Ingestion_Energie`.

5. Validez.

## Étape 9 — Ajouter les fichiers

1. Ajoutez `ingestion_energie.py` comme **Main definition file**.
2. Ajoutez `energie_sjd_utils.py` comme **Reference file**.
3. Enregistrez.

Dans la Spark Job Definition, l'import reste :

```python

```

N'utilisez pas `from builtin...` dans la Spark Job Definition. Le préfixe `builtin` concerne uniquement les ressources d'un notebook.

1. Ouvrez les paramètres de la Spark Job Definition.
2. Sélectionnez `LH_Energie_Bronze` comme Lakehouse par défaut.
3. Utilisez le Starter Pool pour l'exercice.
4. Enregistrez.

Sans Lakehouse par défaut, `Files/landing_sjd` et les tables Delta ne peuvent pas être résolus.

## Étape 11 — Première configuration


# Dépannage rapide

| Erreur | Cause | Correction |
| --- | --- | --- |
| `No module named builtin.energie_sjd_utils` | Ressource absente du notebook | Charger le fichier dans **Ressources intégrées** |
| `No module named energie_sjd_utils` dans la SJD | Référence absente | Ajouter le fichier comme **Reference file** |
| `invalid choice: solaire` | Mauvais dataset | Utiliser `production-solaire` |
| `invalid choice: eolien` | Mauvais dataset | Utiliser `production-eolienne` |
| `Files/landing_sjd` introuvable | Lakehouse ou fichiers absents | Attacher le Lakehouse et contrôler les fichiers |
| Table absente | Job en échec ou mauvais Lakehouse | Consulter les journaux et la configuration |
| 60 lignes après deux exécutions | Ajout au lieu du `MERGE` | Utiliser `fusionner_delta()` du script fourni |
| Échec API | Service arrêté ou URL incorrecte | Revenir au mode `files` |
